# 🧾 一般企业直接法现金流量表编制与校验

这是一套给财务人员、审计人员和项目助理使用的现金流量表工具。它可以读取序时账、现金流量明细以及客户已经编好的现金流量表，自动编制一般企业直接法现金流量表正表，也可以核对客户现有正表是否正确。

使用者不需要会编程，不需要知道表格属于哪一种内部类型，也不需要把原始资料整理成固定模板。即使文件里有合并单元格、多行表头、重复表头、隐藏列、不统一的列名，或者按月份、银行账户拆成多个工作表，系统也会先理解表格结构，再决定怎样读取。每个被识别为业务数据的工作表都会单独登记，不会只读取第一个工作表。

## 🎯 它能帮你做什么

- 根据序时账或现金流量明细编制现金流量表正表。
- 将系统编制结果与客户现有正表逐项核对，并列出差异。
- 检查已有现金流量项目是否与业务内容、收付方向相符。
- 识别现金内部划转，避免同一笔资金在流入和流出中重复反映。
- 识别跨文件疑似重复业务，但不会擅自删除任何一笔记录。
- 计算现金及现金等价物净增加额，并与期初、期末余额进行勾稽核对。
- 保存每一笔业务从原始位置到最终分类的判断过程，方便人工复核。
- 把真正需要人工判断的事项集中在少量表格中，不让人从几千行、几万行明细中重新翻找。

## 👥 哪些情况适合使用

本工具适用于一般企业的直接法现金流量表正表。常见资料都可以处理，例如：

- 普通序时账，没有填写现金流量项目。
- 普通序时账，现金流量项目填写在货币资金科目一侧。
- 普通序时账，现金流量项目填写在货币资金对方科目一侧。
- 已经完成一借一贷配对的序时账。
- 只保留货币资金一侧的现金流量明细。
- 只保留货币资金对方科目一侧的现金流量明细。
- 只有摘要、借贷方向、金额和现金流量项目的明细。
- 按不同现金流量项目分别导出的多个明细文件。
- 客户已经编制好的现金流量表正表。

你不需要判断自己属于上面哪一种情况。把本期有关文件一次选中即可，系统会自行识别。

## 📦 开始前需要准备什么

### 必须提供的资料

1. 本期序时账或现金流量明细，至少提供其中一种。
2. 财务报表整体重要性。
3. 实际执行的重要性。
4. 明显微小错报临界值。

三项重要性通常应直接取自本项目审计工作底稿，并且必须满足：明显微小错报临界值小于实际执行的重要性，实际执行的重要性小于财务报表整体重要性。

如果项目组还没有确定这三个金额，应先按照事务所采用的实务比例完成重要性测算。系统不会替使用者猜测或随意编造金额。

### 只在需要时提供的资料

- 如果要核对客户现有正表，再提供客户已经编制的现金流量表。
- 如果现有资料无法取得期初、期末现金及现金等价物余额，再补充科目余额表或明确的余额数据。
- 如果企业存在汇率变动影响，而且现有资料无法可靠识别，再补充经确认的汇率变动影响金额。

不要一开始就准备一大堆可能用不到的资料。系统会先使用现有文件，只有确实缺少关键证据时才提示补充。

## 📄 支持什么文件

- 支持扩展名为 .xlsx 的工作簿。
- 支持只读处理扩展名为 .xlsm 的工作簿，但不会执行其中的宏。
- 不支持旧式 .xls 文件。遇到这种文件，请先用 Excel 打开，再另存为 .xlsx 后重新选择。

系统只读取原始文件，不会改写原文件。处理开始时会记录文件的数字指纹，后续每个阶段都会再次检查；如果原文件在处理中被改动，系统会停止使用旧的运行结果，防止新旧数据混在一起。

## 🚀 最简单的使用方法

### 第一步：告诉智能助手你要做什么

直接说明你要“编制一般企业直接法现金流量表正表”，或者要“核对客户现有的直接法现金流量表正表”。不需要提供文件路径，也不需要描述表头在哪一行。

### 第二步：在弹出的窗口中选择文件

系统会弹出 Windows 文件选择窗口。请一次选择本期序时账、现金流量明细，以及需要核对的客户正表。可以同时选择多个文件。

如果同一个文件被重复选择，系统会通过数字指纹识别完全相同的文件，只登记一次，不会造成重复计算。

如果要核对客户已经编好的正表，建议直接告诉系统哪个文件是正表。指定后系统按内容识别该文件中的正表页，认不出来会明确报错；该文件里的明细页仍会照常读取，不会丢失。其余文件同样先读明细，再自动识别是否有疑似正表页。不指定正表时，系统发现疑似正表页会先提问确认，不会悄悄采用或丢弃；在疑似正表未确认纳入核对前，结果不会标记为“最终可使用”。

### 第三步：提供三项重要性金额

按照系统提示，依次提供财务报表整体重要性、实际执行的重要性和明显微小错报临界值，金额单位为人民币元。

这三个金额的作用不同：

- 财务报表整体重要性用于说明整个项目的重要程度。
- 实际执行的重要性用于判断剩余不确定事项是否重大到需要人工处理。
- 明显微小错报临界值用于过滤金额很小的模糊事项，避免人工智能和人工把时间浪费在明显不重要的项目上。

### 第四步：必要时确认字段

系统会自动寻找日期、凭证号、摘要、科目、对方科目、借方金额、贷方金额、现金流量金额和现金流量项目等字段。

绝大多数文件不需要人工干预。只有两列含义非常接近、系统无法唯一判断时，才会把具体文件、工作表、推荐列和备选列展示出来请你确认。确认后会在同一次处理中继续计算，不需要重新启动，也不需要重新选择文件。

如果客户现有正表包含普通自定义明细行，系统会把它挂到前一个标准项目下，只用于核对，不会重复汇总。如果出现无法归属的客户自定义总额，系统会明确停止并提示先在原表补充标准项目名称，不会把客户正表误当成序时账反复提问。

### 第五步：确认现金范围

系统会列出可能属于现金及现金等价物的科目，例如库存现金、银行存款、其他货币资金，以及名称中含有保证金、冻结、受限、质押或监管字样的科目。

普通现金科目会给出纳入建议。受限资金和保证金不会被悄悄算作现金，需要根据项目实际情况确认纳入或排除。每个候选科目都必须有明确决定，确认一次后即可继续。

### 第六步：等待系统完成全量计算

系统会扫描全部有效明细，不是只抽查大额项目。它会恢复每张凭证的现金变化，排除现金账户之间的内部划转，再为每个现金流业务组成给出一个唯一的首选分类。

如果一笔凭证同时涉及多个现金流量项目，系统会按照能够取得的项目金额拆分，但拆分后的合计必须与该凭证的实际现金变化一致。无法取得对方科目时，系统不会凭空编造对方科目。

没有现金流量项目的复合凭证不会因为出现多个非现金科目就被机械拆散。例如采购材料同时形成进项税额时，整笔现金支付仍作为同一项采购现金流处理；只有现金流量项目已经分别标注，或者借款本金和利息等业务性质可以明确分开的情况，才会拆成多个业务组成。

### 第七步：处理少量需要人工智能复核的事项

金额小于明显微小错报临界值的模糊事项，直接接受系统首选，不送人工智能复核。

达到筛选条件的模糊事项会被编号，并实际保存成每批不超过 25 项的独立复核文件。人工智能只能看到这些被选中的事项，不会假装看过全部明细。返回结果必须逐编号对应；漏答、重复回答、编号错误或项目无效，都会被系统拒绝。

复核结果可以按批次逐个导入。已经合格导入的编号会被保留，后续批次不需要再次提交；同一编号重复提交完全相同的结果不会重复累计，提交互相冲突的结果则会被明确拒绝。

如果人工智能判断与系统首选不一致，系统会生成第二轮裁决任务。高质量裁决证据可以改变最终分类；低置信裁决不能静默覆盖高证据规则。仍然无法收口且最不利影响达到实际执行的重要性时，事项才会进入最终工作簿的人工确认区。

逐笔判断完成后，系统还会检查同一来源文件、同一凭证、同一摘要的业务组成是否被分到不同现金流量项目。这里不是简单地把同凭证全部改成一个项目，而是把整组的摘要、科目、金额方向和当前理由放在一起复核：共同业务实质相同的统一项目；借款本金与利息、收款与银行手续费、保险费与车船税等确有不同业务实质的，保留拆分并记录理由。

一致性复核按三项重要性分层：组内绝对金额合计低于明显微小错报临界值只留痕；达到明显微小错报临界值但低于实际执行重要性时做一轮复核；达到实际执行重要性但低于整体重要性时必须由第二轮高置信度裁决；达到整体重要性时，两轮都必须是高置信度且逐条结论完全一致，否则转入人工确认。判断依据是整组业务证据，不靠不断新增业务关键词打补丁。

### 第八步：打开结果工作簿

处理完成后，结果默认保存在第一个输入文件所在目录下的“直接法现流表结果”文件夹中。每次运行都会建立一个带日期、时间和唯一标识的新文件夹，因此不会覆盖以前的结果。

主要成果文件名为“现金流量表正表及复核底稿.xlsx”。同一运行文件夹内还会有“计算留痕数据”文件夹，用于保存自动计算基线、运行状态、字段映射、人工智能请求与结果等过程资料。

如果结果因缺少期初余额、期末余额或汇率变动影响而处于草稿状态，可以在原运行中补充这三个金额和资料来源说明。系统会保留前面的识别、现金范围、分类和复核结果，重新形成一份带“重建”标识的新工作簿，不覆盖原草稿。

## 🧠 系统到底怎样判断

### 先理解表格，不按固定位置死读

系统不会规定“摘要必须在第三列”或“表头必须在第一行”。它会查看合并区域、多层表头、列标题组合和列内数据特征，理解每一列代表什么。文件中间再次出现表头、真正的合计行或空白结构行时，也会单独识别，避免把它们当成业务记录。摘要中只是碰巧出现“合计”二字的正常业务不会被直接删除。无法识别的金额和借贷方向会连同文件、工作表和单元格位置写入留痕，不会无声消失；只要仍有这类错误，结果就会保持草稿状态。

### 再把不同资料还原成统一业务

有的文件保留整张凭证，有的只保留货币资金一侧，有的只保留对方科目一侧，还有的只剩摘要和金额。系统会根据现有证据恢复现金增加或减少，并明确记录证据强弱。

如果文件只保留货币资金的对方科目，但“对方科目”列明确写着银行存款等已确认现金科目，即使没有单独的现金流量金额列，系统也会根据借贷发生额还原现金方向和金额，不会把整笔业务漏掉。

如果只有摘要、方向、金额和现金流量项目，而且无法知道保留的是现金一侧还是对方科目一侧，系统会优先使用现金流量项目本身的“收到”或“支付”方向。负数仍按原项目冲减，不会因为出现负号就随意换到另一个项目。

### 排除现金内部划转

银行账户之间转款、现金存入银行、从银行提取现金等事项，只改变现金存放位置，没有改变企业现金总额。系统只有在对方明确属于已确认现金范围，或者整张凭证扣除有证据的对外收支后仍剩下金额相等、方向相反的现金腿时，才排除内部划转。不会再因为同一凭证恰好同时出现两个现金账户，就把真实收款和手续费互相抵掉。

同一凭证既有真实流入又有真实流出时，系统会分别保留两个方向，不会把少数方向强行改成凭证净额方向。偿还借款本金和利息等组合凭证，会按非现金对方科目的实际金额分别形成业务组成。

### 按明确证据优先分类

系统先识别投资活动和筹资活动的明确证据，例如购建固定资产、收回投资、支付投资款、吸收投资、取得借款、偿还借款、支付股利和利息。之后再识别销售收款、采购付款、职工薪酬、税费等经营活动。

程序分类时只把摘要、对方科目和现金收付方向当作业务证据。原资料已经填写的一般企业标准正表项目全称不参与规则匹配，只在找不到足够业务证据时作为低证据保底，不能因为名称写得标准就提高可信程度。

如果业务证据已经明确指向某个项目，程序优先采用业务判断。原标签与业务判断一致时，只作为补充说明；二者不一致时，仍以业务判断作为系统首选并进入相应复核。高证据冲突达到明显微小错报临界值即送人工智能复核；中、低证据事项达到实际执行的重要性才送人工智能复核。每笔判断理由会直接写清命中的摘要、对方科目、收付方向和完整项目名称，不再只展示内部规则代号。

普通往来款默认归入“收到其他与经营活动有关的现金”或“支付其他与经营活动有关的现金”。只有摘要或科目明确说明属于投资活动或筹资活动时，才改变这个默认分类。

一般企业的银行存款利息按经营活动处理；债券投资、贷款投资、应收利息或投资收益等明确投资证据对应的利息按投资活动处理。退款和冲减按原项目以负数反映。

### 用重要性控制复核范围

程序规则负责全量扫描，人工智能只复核达到筛选条件的小部分事项，人工只处理自动判断仍未收口、并且最不利影响达到实际执行的重要性的重大剩余事项。

这意味着“重要待复核事项”完全可以为空。为空不是漏做，而是说明没有事项同时满足“仍不确定”和“金额重大”这两个条件。

### 最后完成正表和现金流量表与货币资金变动的勾稽核对

所有业务先汇总到一般企业标准正表项目，再计算经营活动、投资活动、筹资活动以及现金净增加额。

如果提供了客户现有正表，系统会把客户项目名称还原到标准项目后逐项比较。客户自定义明细行只用于理解和核对，不会重复计入标准正表。

客户正表不要求放在第一个工作表，也可以使用“本年金额、上年金额”或“本期金额、上期金额”等常见表头。系统会扫描全部工作表；如果同一文件中识别到两张都像完整现金流量表的工作表，会要求明确选择，不会擅自取第一张。

现金净增加额还会与期初、期末现金及现金等价物余额核对。汇率变动影响只能来自可识别资料或客户确认金额，系统不会用差额倒挤一个看似平衡的数字。

## 📊 结果工作簿怎样看

结果工作簿固定包含十张工作表。其中“AI复核记录”和“输入识别与字段映射”默认隐藏，避免机器留痕干扰日常阅读；需要追溯时可在 Excel 中取消隐藏。其余工作表建议按下面顺序查看。

### 1. 使用说明与状态

先看这里。它会用中文告诉你当前结果是“最终可使用”“待完成人工确认”，还是“草稿：现金流量表与货币资金变动的勾稽核对未完成或存在差异”“草稿：存在未核对的疑似正表”。人工确认完成后，状态会随工作簿公式自动更新。页面还提供其他工作表的跳转入口。

### 2. 现金流量表正表

这是最终要使用的正表。表中同时保留上期金额、自动计算基线、人工调整和最终金额，方便看清最终数字是怎样形成的。

### 3. 正表核对报告

只有提供客户现有正表时才会形成逐项核对。它会列出客户金额、系统金额、人工调整、最终金额、差异和支持该金额的业务组成。没有提供客户正表时，这张表会明确说明本次属于编制任务。

### 4. 重要待复核事项

这里只放金额达到人工门槛，而且自动判断仍未收口的事项。蓝色单元格初始为空，必须选择“认可自动判断”或该批次真实存在的备选项目，不能在全部正表项目中随意选择。正表会自动更新，不需要再次运行整个工具。

即使有人绕过下拉框直接粘贴任意文字，工作簿也会显示“无效选择”，对应调整金额保持为零，首页不会变成“最终可使用”。跨流入、流出方向改列时，工作簿会根据原始现金方向重新换算目标项目金额，不会简单照搬原列正负号。

如果这张表显示“本期无重大剩余不确定事项”，说明不需要人工处理。

### 5. 疑似重复事项

这里列出跨文件看起来可能重复的业务。系统默认保留，因为“看起来相同”不等于“一定重复”。只有人工确认确实重复后，才在蓝色单元格中选择“剔除”；选择“保留”则不调整。系统只形成调整，不删除原始业务记录。跨项目重复会按被剔除业务的最终标准项目调整，不会产生无项目的失效公式。

重复事项按跨文件一对一配对。同一文件中两笔本来就相同的正常业务，不会因为另一个文件中出现一笔相同记录而被整组当成三笔重复。

### 6. 人工智能复核记录

这里只记录实际送给人工智能的编号化事项及其回答。它不能证明人工智能看过全部明细；全部明细是由程序规则扫描的。

首次复核和冲突裁决分别标明阶段，两轮记录都会保留，不会只留下第一轮答案。

### 7. 原表与自动判定差异

这里逐行列出原明细“主表项目名称”与自动判定现流项目不一致的记录。页面保留原表文字，同时列出原项目标准化结果和自动判定项目；实际比较使用标准化后的原项目，因此不会因为空格、标点等写法差异制造假差异。无法标准化的原项目，以及自动判定为“不进入正表”的记录，也会明确列出。

页面尽量保留日期、凭证字、凭证号、摘要、科目编码、科目名称、借方、贷方、流量金额（原币）、主表项目名称、对方科目和原始位置；原资料没有的字段留空。这张表只用于展示和复核，没有人工修改栏，不参与正表金额、勾稽核对或首页最终状态计算。

### 8. 现金范围与现金流量表与货币资金变动的勾稽核对

这里可以查看哪些科目被纳入现金范围，以及期初余额、期末余额、现金净增加额和汇率变动影响是否勾稽一致。

本期现金净增加额、勾稽差异和首页最终状态都引用人工确认后的正表最终金额。人工改列或剔除重复事项后，现金流量表与货币资金变动的勾稽核对会同步重新计算，不会继续显示调整前的静态结果。

### 9. 全量分类留痕

这里保存每个现金流业务组成的摘要、现金变化、原现金流量项目、对方科目、自动判定现流项目、判断理由、证据强度、异常、方向依据、原始文件、工作表和单元格位置。人读栏目只显示完整项目名称；命中规则、业务组成编号和来源占用键三列技术追溯信息放在最右侧并默认隐藏。被排除的现金内部划转也单独留痕。需要抽查某个正表金额时，可以从这里追查到原始文件中的相关记录。

### 10. 输入识别与字段映射

这里记录每个文件使用了哪些工作表、表头位于哪几行，以及日期、摘要、科目、金额等字段分别取自哪一列。被排除的结构行和无法识别的业务行也会列明位置和原因，用于证明系统是怎样理解原始表格的。

## 🟦 哪些地方需要人工填写

最终工作簿中，蓝色单元格才是允许人工选择的区域，主要出现在“重要待复核事项”和“疑似重复事项”。正表公式、核对报告和其他自动计算区域已经锁定，用于防止误删误改；这种保护用于减少操作失误，不是文件加密。

不要直接覆盖自动计算基线，也不要删除全量留痕。人工选择会通过工作簿内的计算关系自动反映到正表，所以不需要修改几万行明细，更不需要再次运行工具。

## ⚠️ 常见提示是什么意思

### “等待字段确认”

表示有两列或多列很像，系统不愿意猜。查看推荐列和示例值，确认真正代表该字段的列即可。

### “等待现金范围确认”

表示现金候选科目已经找出，需要确认哪些纳入现金及现金等价物。受限资金、保证金等应结合企业实际用途判断。

### “人工智能未完成”

表示某些编号漏答、重复、回答格式不合格或项目无效。系统不会在回答不完整时生成最终结果。

### “人工智能待裁决”

表示人工智能判断与系统首选不同，已经生成第二轮裁决任务。完成裁决后才能继续。

### “现金流量表与货币资金变动的勾稽核对：未完成”

通常表示缺少期初余额、期末余额或明确的汇率变动影响。已完成的分类和正表计算会保留，但结果不会冒充最终可用。取得补充资料后，在原运行中填写三个金额和资料来源说明即可，不需要重选原始文件。

### “输入文件已被修改”

表示原始文件的数字指纹与开始处理时不同。请使用修改后的文件建立一次新运行，不要把旧过程数据继续接到新文件上。

### “发现疑似重复事项”

这只是提醒，不等于系统认定重复。金额较小的疑似重复会列示但不阻止完成；可能造成重大影响的疑似重复，需要人工确认后才能把结果视为最终可用。

## 🔐 原始资料和结果是否安全

- 原始工作簿始终只读，系统不会改写或覆盖。
- 每次运行使用独立文件夹，不覆盖以前的结果。
- 完全重复文件只登记一次，疑似业务重复默认保留。
- 身份证号、长账号和手机号码在送交人工智能前会被遮蔽。
- 自动计算过程保存在独立留痕资料中，人工修改后的 Excel 工作簿才是最终结果。
- 结果工作簿设置为打开时自动计算。使用 Excel 修改蓝色单元格并保存后，公式结果会一并保存；少数不会重新计算工作簿的第三方读取工具，可能只能读到上次保存的公式结果。
- 测试资料只包含匿名合成数据，不包含真实客户资料。

## ❓ 常见问题

### 我不知道现金流量项目标在货币资金一侧还是对方科目一侧，怎么办？

不需要提前判断。系统会结合科目名称、凭证整体结构、借贷方向和项目位置识别。只有现有证据确实无法唯一判断时才会提问。

### 我的文件每个现金流量项目单独导出一个工作簿，可以吗？

可以。一次选中全部文件即可。系统会识别完全重复文件，并对跨文件疑似重复业务单独列示。

### 文件只有摘要、方向、金额和现金流量项目，还能用吗？

可以，但这种资料的证据较弱。系统会全量计算，金额小于明显微小错报临界值的事项接受系统首选，达到筛选条件的模糊事项才交给人工智能复核，从而把复核数量控制在合理范围内。

### 为什么小金额方向异常没有全部送去复核？

因为项目已经设置明显微小错报临界值。低于该金额的事项即使方向或摘要不够清楚，也接受系统首选，避免把大量时间花在不会影响报表结论的微小项目上。

### 为什么普通往来款被放在其他经营活动？

这是系统的默认实务规则。只有摘要或科目明确表明属于投资活动或筹资活动时，才会改列到相应活动。

### 重要待复核事项为空，是不是系统漏掉了？

不是。系统规则已经扫描全部业务，人工智能也只处理达到筛选条件的事项。该表为空表示自动判断已经收口，或者剩余不确定事项的最不利影响没有达到实际执行的重要性。

### 修改蓝色单元格后，需要重新运行吗？

不需要。蓝色区域的选择会自动反映到正表，保存工作簿即可。

### 没有期初、期末现金余额，还能先看正表吗？

可以。系统会保留已经完成的正表和分类留痕，但状态会显示“现金流量表与货币资金变动的勾稽核对：未完成”。补齐资料并完成勾稽核对前，不应把它当成最终可用结果。

### 2026-08-17（准则列报补全：净额迁移 + 租赁与购建相关税费的归类）

继续依据《企业会计准则第31号——现金流量表》应用指南和《企业会计准则第21号——租赁》复核意见，补全上一轮遗留的三类口径问题。

- **净额为负自动迁移**（应用指南三（二）3、4、5）："处置固定资产、无形资产和其他长期资产收回的现金净额"和"处置子公司及其他营业单位收到的现金净额"合计为负时，自动移入"支付其他与投资活动有关的现金"；"取得子公司及其他营业单位支付的现金净额"为负时，自动移入"收到其他与投资活动有关的现金"。迁移连同支撑组成编号一并转移，全量分类留痕仍可逐笔追溯；净额为正时保持原项目不动。除这三个准则明确的"净额"项目外，其余项目出现负数属于退款冲减性质，按准则第五条总额列报原则留在原项目以负数反映，不迁移。
- **租赁与分期付款归入筹资活动**（租赁准则第53条、应用指南）：摘要含"租赁负债 / 使用权资产 / 融资租赁 / 分期付款购建 / 分期付款购买固定资产"的付款，高证据归入"支付其他与筹资活动有关的现金"。简化处理的普通经营租赁租金（如"支付办公楼租金"）不受影响，仍按经营活动处理。
- **契税、车辆购置税随资产购建归类**：二者是取得不动产、车辆的直接相关税费，从"支付的各项税费"移入"购建固定资产、无形资产和其他长期资产支付的现金"。
- **缴回留抵退税款归入"支付的各项税费"**（应用指南明确列举）：原先因摘要含"退税"被排除词挡住落兜底，现新增专门词条高证据归税费；收到留抵退税款仍归"收到的税费返还"，不受影响。
- 自动化测试从 210 项增至 222 项并全部通过，新增用例覆盖三个净额项目双向迁移、迁移不动正数、租赁三类场景、普通租金回归保护、契税与车辆购置税、缴回与收到留抵退税双向场景。

### 2026-08-17（按准则修正三条分类规则 + 内置准则依据）

本次更新依据《企业会计准则第31号——现金流量表》及其应用指南、《监管规则适用指引——会计类第1号》逐条复核全部自动分类规则，修正三条与准则口径不一致的规则，并把准则依据内置到工具中。

- **内置准则依据，判断不许猜**：准则原文及应用指南、现金流量表知识库汇编已放入 `references/准则原文/` 与 `references/知识库/`。人工智能复核时必须按“分类规则 → 准则原文 → 知识库 → 财政部官网”的顺序寻找依据，判断理由必须写明引用的文件名和条款；找不到依据的，如实标注“未找到明确依据”并送人工判断，不得凭经验猜测。
- **代扣代缴个人所得税改归“支付给职工以及为职工支付的现金”**（应用指南三（一）5：企业代扣代缴的个税列入该项目，不属于“支付的各项税费”）。摘要写“代扣个人所得税 / 代扣个税 / 代扣代缴个税”的高证据归入职工薪酬项目；摘要只写“缴纳个人所得税”的不再直接高证据归税费，仅在“应交税费”为唯一对方科目时按中证据兜底并送人工智能复核。
- **票据贴现不再高证据归入“销售商品、提供劳务收到的现金”**：贴现是否附追索权决定其应列经营活动还是筹资活动流入（会计类第1号指引），仅凭“票据贴现”四个字证据不足，现落入低证据兜底并送复核。票据到期收款不受影响，仍归销售回款。
- **理财、结构性存款赎回本金改归“收回投资收到的现金”**（应用指南三（二）1）：摘要含“赎回理财 / 理财赎回 / 收回理财 / 结构性存款赎回”等字样的本金流入高证据归入收回投资项目；只有利息、收益部分仍归“取得投资收益收到的现金”，结构性存款类规则不再把带“赎回 / 收回 / 本金”字样的业务误判为投资收益。
- **修复“唯一对方科目”规则长期失效**：对方科目带明细级次（如“应交税费_应交个人所得税”）时原先因要求科目名完全一致而永远不命中，现按包含关系识别，该中证据兜底规则恢复正常，并使用规则自身声明的证据等级与专属判断理由。
- 自动化测试从 203 项增至 210 项并全部通过，新增测试覆盖上述三条规则修正、唯一对方科目兜底及企业所得税、票据到期收款、结构性存款利息三项回归保护。

### 2026-08-17（日期按格式识别 + 增值税伴随交易）

- 日期列现在**按数据格式自动识别**：某列非空采样值 ≥60% 符合严格日期格式（`YYYY-MM-DD` / `YYYY/MM/DD` / `YYYY.MM.DD` / `YYYY年M月D日`，可带时分秒）即作为凭证日期候选，不再依赖“列名里必须写日期/会计月等词”。表头词命中仍优先；同表多日期列沿用提问机制。
- 增值税遵循“伴随交易”归类（依据《企业会计准则第31号——现金流量表》应用指南）：付款时同时付的**进项税额**随这笔采购或接受的劳务一并归入“购买商品、接受劳务支付的现金”（接受劳务类服务费——律师费、商管服务费、审计/会计/咨询费等——统一并入该项目，不再因对方科目含应交税费就归“支付的各项税费”）；收款时同时收的**销项税额**随销售归入“销售商品、提供劳务收到的现金”。
- “支付的各项税费（CFO-06）”只在**单独向税务机关缴纳税款**（摘要确认为缴税）时触发，并增加兜底：若“应交税费”是现金流出凭证的唯一非现金对方科目，仍按税费处理（证据不足送 AI）。

### 2026-08-17（凭证日期识别增强）

- 字段语义词典新增“会计月”作为“凭证日期”的别名。此前只识别“记账日期 / 凭证日期 / 日期”，如果序时账把日期列的表头写成“会计月”（例如“2026-02-26”按会计月导出），日期列不会被当成凭证日期。
- 后果是凭证身份只剩“凭证号”，不同月份的同一编号凭证（如每月都有的“记-0010”）会被误当成同一张凭证合并，进而把当月的收租、收水电、预存水电、手续费、借款本息等不同业务揉进同一个现金流业务组成。
- 现在“会计月”会被自动映射为凭证日期，凭证身份 = 文件 + 工作表 + 凭证日期 + 凭证号，不再跨月份错误合并。该修复对既有运行没有追溯效果，遇到此类文件需要重新预检形成一次新运行。

### 2026-08-17

本次更新把“原现流项目”彻底从业务规则匹配中分离。项目名称写得和标准名称一样，只能说明原表这样标过，不能证明业务实质真的属于该项目。

#### 🔗 同一业务组一致性复核

- 新增同一来源文件、同一凭证、同一摘要的整组复核。只有组内项目不一致时才触发，不改变已经一致的正常业务。
- 复核读取整组摘要、对方科目、金额方向、原项目、当前项目和判断理由；可以统一项目，也可以对借款本金与利息等确有不同实质的组成保留拆分并说明依据。
- 一致性复核按本项目三项重要性分层：组内绝对金额合计低于明显微小错报临界值只留痕；达到明显微小错报临界值但低于实际执行重要性时做一轮复核；达到实际执行重要性但低于财务报表整体重要性时要求第二轮高置信度裁决；达到财务报表整体重要性时要求两轮均为高置信度且逐条结论完全一致。达到实际执行重要性后仍未收口的整组进入人工确认。
- 一致性复核状态、理由和重要性层级写入“全量分类留痕”；业务组编号属于机器回查字段，默认隐藏。
- 人工确认按整组最不利影响判断，同一未收口业务组的每个真实组成只出现一次，不会与逐笔未收口事项重复。

- 排除词只检查摘要和原现金流量项目，不再扫描客户或供应商名称，避免名称含“投资”等字样误伤销售回款。
- 扩充销售退款、退回客户货款、退回采购款等常见表达，继续按原项目负数反映。
- 普通往来款默认其他经营活动的既定规则保持不变，不因为证据等级为中等就把所有大额往来款送人工。

#### 🤖 人工智能与人工确认

- 首次复核和冲突裁决均实际拆成每批不超过 25 项的独立逐行记录文件，不再生成一个不受批次上限约束的全量请求文件。
- 低置信裁决不能覆盖高证据系统结论；证据不足时保留系统首选并进入剩余不确定性的重要性判断。
- 只有现金一侧或只有摘要的弱证据明细仍按重要性筛选；保留的是对方科目且已有可用科目证据时，不再仅因“单边来源”标记就全量送人工智能。
- 人工复核蓝色单元格初始为空，只允许选择“认可自动判断”或该批次真实备选项目，不再开放全部标准项目。
- 重要待复核和重大疑似重复未确认时，首页状态显示“待完成人工确认”；填完后公式自动改为“最终可使用”。

#### 📊 正表、核对报告与现金流量表与货币资金变动的勾稽核对

- 客户现有正表的上期金额已回填到输出正表。
- 普通客户自定义明细行会挂到前一个标准叶子项目用于核对；无法归属的客户自定义总额会给出明确错误，不再误入序时账字段确认循环。
- 正表核对报告改为引用正表的自动基线、人工调整和最终金额；人工选择后差异会同步更新。
- 勾稽核对页统一列示期初、汇率影响、本期净增加、期末和勾稽差异，差异列不会因首行表头缺失而消失。
- 新增同一运行内补充期初、期末、汇率影响和资料来源说明的入口。补充后保留前序计算并生成新工作簿，不覆盖草稿。
- 状态改为面向使用者的中文，不再直接显示内部英文状态码。
- 失败恢复改为先生成临时工作簿并完成验收，再形成正式文件；状态指向的文件缺失或损坏时允许重建，既有疑似残留文件不会被覆盖。

#### 🛡️ 工作簿与留痕

- 正表公式、核对报告和自动计算区启用防误改保护，蓝色人工选择格保持可编辑。
- 全量留痕等工作表的打印区域按实际行数设置，不再固定到第 101 行。
- 跨项目疑似重复按被剔除业务的最终标准项目形成调整，不再产生空项目调整公式。

- 命令帮助中“字段映射确认”和“现金范围决定”的说明已分开。

#### 📝 两项未按复核报告原建议修改的结论

- “中等证据大额往来款没有复核路径”不作为缺陷修改。此前已经明确：普通往来款由系统给出唯一经营活动首选，只有真正模糊且达到筛选条件的交易才交给人工智能；把全部大额往来款送审会违背减少人工复核数量的目标。
- “工作簿公式缓存值全部为零”与实际代码不符。正表公式在生成时写入了自动基线缓存值，人工调整公式在尚未填写时缓存为零是正确状态。本次没有伪造人工调整后的缓存值，而是在使用说明中补充：应使用 Excel 打开、重新计算并保存，少数不重算公式的第三方工具可能只能读取上次保存结果。
