# 统一规则中心

## 目的

现金流分类仍由各处理模块执行，但所有会影响候选、评分、行动、勾稽和最终工作簿的规则，都必须先在统一规则中心登记，再由同一个入口加载、校验和提供调用。任何业务模块不得另存一份行动表、失败出口、兜底顺序或工作簿结构。

## 唯一入口

统一入口为 `src/cashflow_direct/rule_registry.py`，入口清单为 `references/规则中心清单.json`。

入口一次加载并校验下列八类规则：

1. 正表项目。
2. 字段识别，包括字段名称、取值类型和已登记的缺失占位提示。
3. 完整科目路径。
4. 摘要语义。
5. 证据评分与行动。
6. 特殊业务与勾稽。
7. 工作簿输出。
8. 标准一级科目基线。

规则按类别分别保存，不合并成一个难以维护的大文件。各模块只向统一入口取自己需要的部分。

字段取值清洗也属于统一规则。上游系统写入“未找到匹配”等提示文字时，只有在字段规则中逐项登记后才能按缺失处理，并且必须保留原行和警告。业务模块不得自行另存一份占位词清单，也不得把未登记的陌生科目静默清空。

摘要中的句首现金动作同样属于统一规则。句首或日期后的单字“收”“付”及其现金方向必须登记在摘要语义规则中，由处理模块统一读取；不得只在程序内写死一侧动作，造成同等明确的收款和付款得到不同处理。

## 统一校验

每次加载规则中心时必须完成以下检查：

1. 必备类别和登记文件齐全。
2. 一般企业正表恰好包含35个唯一项目，项目现金方向合法，公式引用存在。
3. 科目路径和摘要规则引用的正表项目存在。
4. 规则编号不重复，规则状态合法，同一类别的明确优先级不冲突。
5. 正常行动表的每个原项目状态、证据分数和重要性档位都有且只有一个动作。
6. 行动分组只引用已启用动作，自动动作与待处理动作不重叠。
7. 已废止的“低金额人工批量”和“人工批量决定”不得重新成为启用动作。
8. 最终工作簿恰好包含规定的13张工作表，低金额事项使用“低金额系统兜底明细”。
9. 差异表独立来源1固定为完整科目路径，独立来源2固定为摘要。

任何一项不通过，运行在读取业务数据前停止，不允许带着半套规则继续计算。

## 规则登记和追溯

统一入口把各类规则整理为相同的登记字段，包括规则编号、名称、类别、适用条件、不适用条件、结果、优先级、制定理由、状态、版本、来源文件和对应测试。原始规则文件不必重复填写相同的类别说明，由入口清单补齐公共登记信息。

首次行动写入具体行动表单元格的规则编号；人工智能复核后的结果写入人工智能结果出口规则编号。最终的“全量分类留痕”同时保存业务语义命中规则、决策规则编号、评分版本、行动表版本和整个规则中心版本。

规则中心指纹覆盖入口清单及其登记的全部规则文件。任何规则文字、条件、项目、动作或输出口径变化，都会改变指纹并使旧运行目录失效。

## 运行参数边界

下列内容不是通用规则，不写死在规则中心：

1. 本次财务报表整体重要性、实际执行重要性和明显微小错报临界值金额。
2. 本次自动修改最低证据分选择。
3. 本公司的现金范围确认结果。
4. 本公司经用户确认的特殊核算规则。
5. 本次期初、期末余额和汇率变动影响。

规则中心只规定这些输入如何校验、如何参与判断和如何留痕。

## 改规则的固定步骤

1. 在所属分类规则文件中修改，不在业务模块另加判断。
2. 登记规则编号、状态、版本、理由和对应测试；需要废止时保留废止记录并删除所有有效出口。
3. 运行规则中心定点测试，确认文件、编号、项目、方向、动作和优先级均合法。
4. 运行全部自动测试、技能结构检查和程序编译检查。
5. 使用用户重新提供的文件和全部参数执行独立冒烟测试，不复用旧运行设置。
