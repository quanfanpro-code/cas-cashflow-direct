## 三、功能需求

### 3.1 现金范围与业务组成门禁

1. 没有已确认纳入现金范围的现金行时，不得因旧现流项目、旧现流金额、摘要、规则或AI结论构造现金业务；单边明细同样适用。
2. 被排除现金账户的旧现流标签不得参与金额拆分、业务组成或分类，只能按权威设计作为有限的对方科目事实使用。
3. 多行业务必须保留原始行身份。不得因为同一凭证号就整体合并为一条强证据业务。
4. 金额连接必须按照设计第7节顺序形成可解释组合；组合不唯一时输出候选组合供确认，不得整单猜测。
5. 不能使用“超过64行直接放弃搜索并整体合并”的方式绕过多业务拆分；大凭证必须有确定、可验证且不丢业务的退化路径。
6. 路径为空、断层、错序、内容属于别行、只有现金科目等情形必须有明确产生方、异常状态和处理出口；`account_path_invalid` 不得只有消费方。

### 3.2 证据质量、来源独立性和评分防线

1. “咨询费”“服务费”等裸词必须按设计第11.5节作为弱或歧义证据，不能直接取得中质量或唯一候选。
2. 只有“应付账款”一级科目不得评为中质量。
3. 来源独立性必须双向判断：摘要比路径多事实、路径比摘要多事实均要评估；两个来源实质重复时不得计为独立。
4. 任何70分结论必须同时具有两个独立来源；来源数不是2时立即停止自动路径，不得依靠后续调用方碰巧拦截。
5. 来源冲突留痕必须记录真实的来源数量和独立性，不得固定写成“两个独立来源”。
6. 摘要语义任务必须覆盖否定、不确定和条件性表达，并将结果用于候选质量和冲突判断。
7. 每个摘要判断、路径判断、规则命中和最终结论必须记录原文及其原始位置，不能只保留命中文字。

### 3.3 动作表与AI复核

1. 修正动作表160格中的五格差异：
   - 55分、原项目与候选冲突、M2不得直接保持，按设计第15节进入“先一次AI确认能否保持，再视结果进入双AI”的路线；
   - 原项目为空或无法标准化、70或90分、M0共四格必须自动补列，不得调用AI。
2. 普通分类AI输入只包含设计允许的原始业务事实和有效规则，不得展示系统候选池；方向检查和退款/冲减强制任务可按设计例外提供必要候选。
3. AI整项漏答必须与非法答案一样累计技术失败；连续三次失败后进入明确终态，不能永久留在队列。
4. 结构任务三次失败后立即转Agent确认终态，不得继续安排新的结构轮次。
5. 多份AI结果不得冒充新的业务证据、提高证据分数或取消已经触发的复核轮次。
6. AI与动作表的最终路由必须满足权威设计，不得用旧测试期望覆盖设计。

### 3.4 公司规则、重大冲减和同类累计

1. 过期、超出适用主体或期间、彼此冲突的公司规则必须转人工，不得静默忽略。
2. “仅本次采用”只影响当前业务，不得作为可传播的活动规则影响后续相同摘要或路径。
3. 重大退款或冲减模式确认必须记录适用主体、期间、影响笔数、影响金额和对后续业务的影响。
4. 同类分组键必须实际包含 `business_object`，不得把 `purpose` 重复使用两次。
5. 累计金额、组成明细、金额档和动作必须完整留痕；单笔与累计不得因中间字段重复或缺口出现不同处理。

### 3.5 决定状态、重复事项和工作簿闭环

1. 疑似重复组存在尚未决定业务时，工作簿仍必须正常生成；重复事项的人工选择单元格必须通过公式联动最终人工项目，禁止以空项目编号查询名称。
2. 非法摘要、非法路径等诊断事项必须在同一最终工作簿中完成必要人工选择，并通过公式更新状态、项目和汇总资格；不得要求重新导入、重新分类或再次运行程序。
3. M3事项为进入工作簿而改成待人工时，运行状态、数据库和工作簿必须使用同一正式状态，禁止仅修改内存副本。
4. 生成前统一校验每一笔排除均有明确原因；任何无原因排除都阻止最终生成。
5. 全量分类留痕的共同列顺序必须符合设计第21.5节，默认视图和隐藏技术列同时满足可读性与可追溯性。
6. 每个最终结果必须明确区分自动、AI、人工、待人工、排除和诊断状态；未取得汇总权限的事项不得进入正表。

### 3.6 版本、登记和需求追踪

1. 运行版本必须同时固定评分/动作表版本、规则版本、重要性及累计规则版本、强制检查版本、代码版本和输入来源标识。
2. 新旧运行记录不能混用；任一影响判断的版本不一致时必须拒绝继续。
3. 建立评分使用位置登记：旧分数、旧阈值、自动改表入口、AI入口、人工入口、累计入口和工作簿汇总入口均有唯一登记和测试。
4. 建立“设计节号—问题编号—代码文件—测试文件—验证结果”追踪矩阵。
5. 建立复核问题闭环，至少覆盖 A-1至A-24、B1至B6、S-3、S-4、S-6、S-7、S-10，逐项记录问题、改动、测试和结果。

1. 天微真实验收只验证通用业务不变量，不得断言具体客户科目集合、名称、金额、行号或关键词。
2. 真实文件未提供或环境变量未设置时可以明确跳过，但不得把跳过表述为“真实验收通过”。

### 3.8 真实工作簿四项严重错误纠偏

1. “重要待复核事项”U列“单笔金额”必须写为Excel数值，金额取业务现金变化绝对值，数字格式与H、I、K等金额列一致；不得从文字留痕反向取值后写成文本。

4. “原表与系统决定差异”继续严格执行权威设计第21.7节：只列无需人工复核、已经由系统或AI确定并确实补填、修改或明确排除原项目的行；待人工事项不得进入。不得通过扩张差异表范围掩盖上游分类未完成。

7. 真实验收必须增加非退化断言：摘要结果不得全量为空候选和空分类事实；有明确业务事实的真实数据必须实际进入双来源判断。验收报告必须列示各分数、原项目状态和动作数量，出现70/90分为0或自动修改为0时必须停下分析原因，不能直接宣告通过。
