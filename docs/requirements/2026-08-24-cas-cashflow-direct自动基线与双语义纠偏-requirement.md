## 1. 背景与问题

本次真实工作簿暴露三个同级根问题：

1. “自动基线”没有以客户正表金额为起点，而是重新汇总已经完成系统决定的业务组成；75项等待人工的业务全部按0计入自动基线，造成客户金额与自动基线之间出现无法由3项系统决定解释的大额差异。
2. 摘要规则没有正确绑定动作、对象和修饰关系。“农民工资专用账户款”中的“工资”被错误当成本公司直接支付职工薪酬；同类机制还把员工备用金退回识别为取得企业借款、把设备货款识别为购买商品、把不同服务对象的个税统一识别为职工支付，并把这些结果评为45分。
3. 完整对方科目路径仍以单个科目段直接给项目和分数，完整父子路径没有成为真正判断单位；大量路径依赖每次运行临时解释，证据质量仍使用解释结果自报的把握程度。

系统定位继续保持为“异常纠偏系统”：原项目能够标准化时，以客户原列报为基线；系统只调整已经取得自动处理权限的异常，人工决定另行反映。

## 2. 用户与使用场景

使用者是编制或复核直接法现金流量表的财务、审计人员。使用者需要从“正表核对报告”直接看清：

- 客户原表金额是多少；
- 系统已经自动改了什么；
- 人工后来改了什么；
- 最终金额是多少；
- 每一项自动修改是否有足够、可追查的摘要和路径证据。

使用者不应为了规则没有读懂一句话或一条科目路径而逐笔证明客户原项目正确。

## 3. 需求一：自动基线以客户金额为起点

### 3.1 固定列关系

“正表核对报告”必须遵守以下唯一关系：

> 客户金额＋系统自动调整＝自动基线
> 自动基线＋人工调整＝最终金额
> 最终金额－客户金额＝差异

系统自动调整包括：

- 自动改判：原项目减少，新项目增加；
- 系统自动补列：相应项目增加；
- 系统自动排除：原项目减少。

人工调整包括：

- 人工改判：原项目减少，新项目增加；
- 人工补列：相应项目增加；
- 人工明确排除：原项目减少。

### 3.2 禁止重复

1. 等待人工复核不得改变自动基线。
2. 人工决定只能进入“人工调整”，不得再次改写自动基线。
3. 自动基线不得以“只有已经完成系统决定的业务组成”为起点重新汇总。
4. 原项目有效且等待人工的业务仍保留在客户金额和自动基线的原项目中，直到人工调整列明确反映新的处理。

### 3.3 两种差额分开

客户正表与输入明细或业务组成重建本身不一致，属于“原表与明细勾稽差额”，不得混入系统自动改判金额，也不得静默改变自动基线。该差额应在现有勾稽材料中单独说明来源。

“原表与系统决定差异”继续只列已经由系统自动完成的改判、补列和明确排除；等待人工事项不进入该表。

### 3.4 验收标准

1. 没有自动改判、补列或自动排除时，每个项目的自动基线等于客户金额，即使存在等待人工事项。
2. 自动改判一笔时，原项目减少、新项目等额增加，净现金不变。
3. 人工作出不同决定前后，自动基线不变；变化只出现在人工调整和最终金额。
4. 真实样本的自动基线差额能由3项现有系统决定逐项解释，不再由75项待人工业务造成大额缺口。
5. 客户正表与明细重建差额另行列示，不伪装成系统决定。

## 4. 需求二：摘要必须正确绑定动作、对象和修饰关系

### 4.1 共同根因

词典中的“工资、借款、货款、采购款、个税”等概念词本身可以保留。错误在于程序把命中的词直接当成本次现金动作的业务对象，没有先判断该词属于账户名称、企业借款、员工备用金、存货采购、长期资产采购、工资收入、分红收入或其他语境；证据质量又把同一个对象词重复当成决定性属性，形成45分。

### 4.2 通用判断要求

程序必须先确定：

1. 本企业的主要收付款动作；
2. 本次交易的直接对象；
3. 收付款对象和受益对象；
4. 项目、合同、资产、费用、收入等用途或属性；
5. 关键词修饰的对象，以及它是否只是更长名称的一部分。

只有这些关系足以唯一排除其他候选时，摘要才可以评为45分。单个对象词不得同时充当“业务对象”和“决定性用途或属性”。

### 4.3 四类真实红线

1. **复合账户名称**：“农民工资专用账户款”等表达中的“工资”未被证明是本公司直接支付职工薪酬时，不得形成职工支付强候选。
2. **借款角色**：员工备用金或个人借款退回不得形成“取得借款收到的现金”；只有企业作为借款主体取得融资本金时，才形成筹资活动借款候选。
3. **货款和采购款对象**：“货款、采购款”本身不能区分存货、长期资产、办公用品、礼品或其他费用，必须结合设备、项目、用途和资产属性；仍有多种合理解释时不得评强。
4. **个人所得税服务对象**：工资个税、分红个税、股权激励个税和无法确定服务对象的个税必须分开解释；服务对象不明时不得统一形成职工支付45分。

### 4.4 Agent边界

1. 已确认句式由固定程序处理。
2. 只有词语修饰关系或复合分句确实无法确定时，才生成受控语言槽位任务。
3. Agent只补“哪个词修饰哪个对象、谁是动作主体或受益对象”等原文关系，不得返回现金流项目、分数或置信度。
4. Skill不得自行启动LM Studio、本地模型或外部模型。
5. 规则或Agent没有形成足够修改证据时，原项目有效的业务保持原项目。

### 4.5 验收标准

1. 将本次发现的29项“摘要45分候选与有效原项目不一致”全部纳入回归核对。
2. 四类红线分别建立不含客户名称、金额、行号和项目编号的通用测试。
3. “农民工资专用账户款”不再形成CFO-05强候选。
4. 员工借款退回不再形成CFF-02强候选。
5. 设备货款不得仅因“货款”形成CFO-04强候选。
6. 服务对象不明的个税不得形成CFO-05强候选。
7. 真实样本中仍评为45分的摘要必须具有动作、对象以及独立的关键用途或属性，不能只靠动作加一个对象词。

## 5. 需求三：完整科目路径必须作为一个整体解释

### 5.1 词典职责

1. 通用词典只识别科目节点可能表达的概念及同义表达，不允许单个科目段直接决定现金流项目和证据分数。
2. 完整一级科目、中间层级、末级明细及限定词共同决定当前路径语境。
3. 完整路径解释优先于单个科目段命中；单个段命中不得跳过完整路径判断。

### 5.2 固定程序与Agent分工

1. 固定程序先规范化节点名称、识别概念、组合父子路径、形成可能项目并判断证据是否足够。
2. 路径能够唯一判断但仍缺少决定性用途、项目或资产属性时，最高为25分；只有完整路径足以唯一排除其他候选时才为45分。
3. 证据质量不得直接使用词典或Agent自报的high、medium、low换算。
4. 固定规则无法解释完整路径关系时，才生成受控路径槽位任务；Agent不得返回项目或分数。
5. 无法可靠解释时保留未识别或多个候选，不为了提高表面覆盖率强行分类。

### 5.3 规则覆盖情况清单

在现有`科目语义词典说明.md`中增加一个汇总区，列明：

- 本次完整路径总数；
- 固定规则已经能够解释的路径数、笔数和金额；
- 只能部分解释、存在多个候选、发生冲突或未识别的路径数、笔数和金额；
- 需要补充的高频或高金额路径。

该清单只用于检查和完善规则，不参与现金流分类，不增加证据、修改权限、人工复核或完成门禁，也不恢复“可靠同类组”。为避免增加无必要工作表，本次默认复用现有说明文件，不新增独立Sheet。

### 5.4 科目编码边界

企业提供稳定科目表时，可以使用同一账套内的科目编码和父子关系提高稳定性；没有科目表时继续使用现有完整路径。不得为本次修复强制增加新的输入文件，也不得把不同企业的自定义编码机械通用化。

### 5.5 验收标准

1. `管理费用_设备款`不得仅因“设备款”形成长期资产项目。
2. `生产成本_鉴定成本_人工_福利`不得仅因“生产成本”形成购买商品项目。
3. 同一末级词位于不同父路径时可以形成不同候选或保留歧义。
4. 完整路径解释不得被无父路径约束的通用段覆盖。
5. 规则覆盖情况清单的数量、笔数和金额能追溯到本次实际业务组成。
6. 覆盖统计不改变任何业务的分类和人工路由。

## 6. 明确不做的内容

1. 不安装或引入HanLP、LTP、结巴、PyTorch、Transformers等中文自然语言处理依赖。
2. 不启动或操作LM Studio。
3. 不为天微或其他客户的名称、金额、行号、项目编号建立专用规则。
4. 不恢复可靠同类组、累计重要性人工确认或相关工作表。
5. 不重复执行十万行性能测试；本批只运行受影响测试和一次必要的真实样本验收。
6. 不重构与三项需求无关的现金范围、业务组成或金额重要性模块。

## 7. 约束与风险

1. 客户正表与明细本身可能不一致，系统必须揭示但不能把该差额冒充自动改判。
2. 摘要和路径都可能信息不足，正确结果可以是低质量或多个候选；不得把覆盖率当成准确率。
3. 现有运行目录保存旧版本语义结果，新版本规则不得与旧结果混用。
4. 工作簿公式和缓存值必须在Microsoft Excel中实际重算后验收。
5. 中文文件继续使用UTF-8 with BOM，并在写入后检查乱码、问号和Unicode替换字符。

## 8. 调研摘要与来源

### 8.1 项目内证据

- 当前`statement.aggregate_statement`跳过全部未解决决定，直接造成待人工业务退出自动基线。
- 本次运行75项待人工的`baseline_statement_amount_cent`全部为0；其中74项原项目能够标准化。
- 本次5,355项唯一摘要中有530项被评为45分，其中493项只包含现金动作和业务对象，没有独立的用途、项目、资产或其他决定性属性。
- 本次有29个业务组成出现“摘要45分唯一候选与有效原项目不一致”，覆盖复合账户名称、员工借款、货款或采购款、个人所得税四类关系绑定问题。
- 本次184条完整路径中，固定通用词典只有15条形成决定性项目，其中14条依赖单个科目段；其余169条依赖本次运行临时解释。

### 8.2 现成方案调研

- [HanLP](https://github.com/hankcs/HanLP)：提供中文分词、命名实体、句法和语义依存等完整能力，维护活跃、成熟度高，但需要模型及较重运行环境，输出也不是现金流会计语义，不能直接满足固定、可复核、可重复的候选和评分要求。
- [LTP](https://github.com/HIT-SCIR/ltp)：提供中文分词、词性、依存句法和语义角色能力，维护活跃，但同样需要模型，并不能替代现金流业务对象、用途、主体和会计项目的固定规则。

结论：本次不引入外部NLP框架。继续复用现有`summary_semantics.py`、`account_dictionary.py`、统一评分中心和工作簿输出结构，在共享入口修正关系绑定、质量判断和基线计算，改动最小、结果可重复，也符合用户明确禁止启动本地模型的边界。
