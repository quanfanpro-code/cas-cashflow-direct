## 一、背景与问题

skill 实际使用中收到三条客户反馈：

1. **反馈1**：客户的现流正表金额列表头叫"2026年1-6月"，程序死抠"本期/本年"字样（`statement.py:166`），识别失败。反馈本意：正表文件名可以任意，用户告诉 agent 看哪个文件即可，程序应按**内容**认出它是现流正表。
2. **反馈2**：找不到正表后程序/执行方自动去文件夹翻找。**用户明确：暂不处理。**
3. **反馈3**：现流明细取数方向出错。病根在 `components.py:_signed_flow`——把"序时账（借贷还原）"和"现流明细（项目名+金额列直接给方向）"混在一套猜方向的逻辑里，且忽略金额符号（红字/红冲）。

## 二、真实文件实测证据

### 清平表（`现金流量-清平.xlsx`）

- `现流表` 工作表：44 行，表头 `项目 | 行次 | 2026年1-6月`，第 1 行为单位抬头 → 触发反馈1 识别失败。
- `明细` 工作表：2895 行，列为 `日期|凭证字|凭证号|分录行号|摘要|科目编码|科目名称|借方|贷方|(空)|流量金额（原币）|(空)|主表项目名称`。
- 数据规律：流量金额平时记正数、红冲记负数（477 行负数）；借贷列有红字负值（61 行）；38 行借贷金额 ≠ 流量金额（凭证含非现金部分，如贴现息），证明**流量金额列才是权威金额**。
- 按现有 `_signed_flow` 推演：约 524 行（18%）现金方向被算反。
- 镜像读法（借贷定方向）与项目名读法方向全表一致，但金额 38 行不一致 → 方向与金额都必须以"项目名 + 流量金额"为准。

### 鼎弘表（`现金流量明细查询-四川省鼎弘非融资担保有限公司.xlsx`）

- 单工作表 407 行 = 394 行明细 + 13 行小计/汇总（小计行无日期、无凭证号，混在明细中，含"现金及现金等价物净增加额 -1469 万"）。
- 核心列：`现金流量表项`、`分配金额`（386 正 / 8 负，负数为红冲）。
- 现有词典**认不出**"分配金额"（flow_amount）和"现金流量表项"（flow_item），整表会被误判为序时账，且小计行会污染汇总。

## 三、用户与使用场景

- 使用者：审计人员（零编程基础），通过 AI agent 调用本 skill 编制现金流量表正表。
- 输入表型目前已知 7 种：序时账类 3 种（甲：借贷+对方科目；乙：借贷+现流项目；丙：齐全）、现流明细类 4 种（丁：现金科目侧+方向列+流量金额；戊：对方科目侧+方向列+金额；清平型：对方科目侧+借贷列+带符号流量金额+项目名；鼎弘型：项目编码+项目名+分配金额+混入小计行）。
- 用户终极目标：**不管来多少种表格，抓住核心列就能正确处理**，不为单一表型打补丁。

## 四、功能范围

### 反馈1（正表识别放宽）

1. 正表识别不再限定金额列叫"本期/本年"，改为按内容特征识别：存在项目类列 + 数值金额列 + 行内容是标准现流项目名（高命中率）。
2. 文件名完全不参与判断。
3. 选文件/引导环节明确：有客户正表时由用户告诉 agent 是哪个文件（文档层面引导同步更新）。

### 反馈3（核心列取数重构）

1. **金额支柱**：识别出流量金额列（词典扩充"流量金额（原币）""分配金额"等叫法）→ 金额一律取它（含正负号）；没有才退回借贷差额。
2. **方向支柱**：识别出现流项目列（词典扩充"现金流量表项"等叫法）→ 项目名能认出收付方向就听项目名的，金额符号照常生效（红冲）；认不出再依次回退：方向列 → 借贷镜像（必须尊重红字负号）。
3. **小计防线**：明细类表中无日期且无凭证号的行视为小计/汇总行，剔除并留痕，不进汇总。
4. 序时账类（甲乙丙，无流量金额列）走原有借贷还原逻辑，行为不变。
