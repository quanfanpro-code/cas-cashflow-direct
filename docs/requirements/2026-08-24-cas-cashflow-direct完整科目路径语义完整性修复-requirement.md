# cas-cashflow-direct完整科目路径语义完整性修复需求

## 一、背景与问题

权威设计要求系统把完整对方科目路径作为一个整体解释，保留已确认的标准一级科目、中间层级、末级明细和限定词，再形成候选项目与0、10、25、45分。任何单个科目段都不得脱离父路径直接决定现金流项目或证据分数。

2026年8月24日真实样本冒烟显示：184条完整路径中，固定规则完整解释65条、部分解释114条、未识别5条。进一步逐层复核发现，本轮虽然修复了部分一级科目和父属性问题，但又遗漏了一批明细节点。例如“税金及附加_车船税”和“应交税费_车船税”只识别父级“税金及附加/应交税费”，没有识别“车船税”；导致360元车船税业务的路径证据从上次45分降为0分，系统未再自动改判。

这不是单一词条问题。当前真实路径中还存在同类缺口：

- 税费明细：车船税、城建税、地方教育附加、环境保护税等；
- 职工薪酬明细：社会保险费及养老、医疗、失业、工伤、大病医疗等；
- 费用和成本层级：费用化支出、直接费用、间接费用、合同履约成本，以及打印装订费、电话费、培训费、餐费、公交地铁等常见明细；
- 结算和金融资产路径：应收票据、应付票据、商业承兑汇票、银行承兑汇票、募集户、一般户及投资对象等；
- 其他能够由父路径、常见同义词或明确限定关系解释，但目前仍被列为未识别槽位的节点。

## 二、用户与使用场景

本需求服务于一般企业直接法现金流量表的真实账套处理。审计人员需要看到系统确实理解了完整路径中的每一层，而不是只保留一级科目、忽略中间或末级明细，再用残缺证据评分。

系统定位仍是异常发现和纠错：完整路径解释用于寻找足以推翻原项目的证据，不用于证明每一笔客户原分类都正确，也不得为了提高覆盖率强行分类。

## 三、功能范围

### 3.1 完整路径逐层保留

每个路径节点必须保留原文、层级位置和解释状态。每一层只能处于以下一种可追溯状态：

1. 固定词典直接识别的概念；
2. 依据明确父子关系继承的父属性；
3. 不改变业务类别的限定信息，例如账户类型、核算对象或通用层级标记；
4. 仍无法可靠解释、需要受限Agent补充的未识别槽位。

不得把任何节点静默丢弃。只有前3类均已说明且路径已形成唯一、无冲突的业务含义时，才能称为“固定规则完整解释”；存在第4类时必须保持“部分解释”或“未识别”。

### 3.2 明细概念和同义词补强

固定概念词典应优先覆盖可跨账套复用的常见明细及其规范化表达，不为当前客户名称、凭证号、金额或行号建立特例。至少覆盖本次已发现的税费、职工薪酬、常见费用、票据结算和投资属性明细。

同一概念的简称、全称和常见后缀应归入同一概念，例如“城建税/城市维护建设税”“环保税/环境保护税”；但增值税、个人所得税、罚款和滞纳金仍按现有专门规则处理，不得混入一般税费规则。

### 3.3 父属性继承

父属性继承必须由完整路径结构控制，不能把父概念机械复制给所有子节点。适用示例包括：

- “应付职工薪酬”下明确的社会保险及其险种继承职工薪酬属性；
- “应交税费/税金及附加”下明确的法定税种继承税费属性；
- “交易性金融资产/长期股权投资”下的账户类型或投资对象保留投资属性，同时把明细标记为账户限定或投资对象；
- 管理费用、销售费用、制造费用、研发支出等路径中的通用层级标记继承费用或成本语境，但设备、维修、折旧、职工薪酬、材料、资本化等决定性明细仍按专门关系改变或限制候选。

### 3.4 完整路径候选和证据质量

候选项目和质量继续由固定程序依据完整路径形成，不由节点词典或Agent直接返回。

- 路径只显示宽泛科目性质且仍有多个合理候选时为10分；
- 路径已唯一指向候选但缺少决定性用途、项目或属性时为25分；
- 路径明确显示对象、用途、项目、资产、税费、投资或筹资属性，能够唯一排除其他候选且无冲突时为45分；
- 特定税种路径属于明确税费属性，应按45分强证据处理。

不得因“固定规则完整解释”这个状态本身机械给45分，也不得因存在不影响分类的账户类型或核算对象而把决定性父属性降为0分。

### 3.5 受限Agent边界

固定规则无法解释的企业专属或新明细，仍可进入受限Agent。Agent只能补节点概念、原文位置和父子关系，不能返回现金流项目、候选、质量、分数、置信度或处理动作。Agent没有可靠补充时，路径继续保持部分解释或未识别，不得伪装成完整覆盖。

本次修复不得调用LM Studio或其他本地、远程大模型处理真实样本；真实冒烟使用固定规则结果验证。

### 3.6 覆盖报告

现有《科目语义词典说明》继续列示：完整路径总数、固定规则完整解释、Agent补充、部分解释、冲突、未识别，以及关联业务组成笔数和绝对金额。

覆盖统计还应能够列出每条路径的全部节点、各节点解释来源、未识别槽位、命中路径规则和最终质量，便于发现“一级科目已识别但明细丢失”的问题。覆盖率只用于完善规则，不参与分类、评分、人工路由或完成门禁。

### 3.7 运行时选择自动修改最低分

以前固定为70分才允许修改客户已有项目。调整后，70分仍是默认值和推荐值，但Agent每次运行都必须先询问客户“系统自动修改客户原项目至少需要多少分”，只提供以下四个合法选项：

| 客户选择 | 可以进入自动修改判断的总分 |
|---:|---|
| 50 | 50、55、70、90 |
| 55 | 55、70、90 |
| 70（默认、推荐） | 70、90 |
| 90 | 90 |

该选择是本次运行的“自动修改最低证据分”，必须写入运行状态和判断留痕，并在最终工作簿或运行说明中显示。客户没有作出选择前，不得继续形成自动修改结果；询问界面应把70列为默认及推荐选项，不得通过技术参数要求客户手工填写任意数字。

该阈值只控制原项目有效且系统拟修改为不同标准项目时的最低证据分，不改变以下规则：

- 摘要和完整路径仍按0、10、25、45四档评分，只形成十种合法总分；
- 来源冲突没有可用总分，不能因阈值降低而自动修改；
- 非法输入、内部划转、现金范围、金额守恒、公司规则冲突、增值税和个人所得税等强制检查仍优先；
- 单笔金额重要性及既有人工责任边界仍然适用，客户选择较低阈值不能绕过必须人工处理的事项；
- 自动补列、人工调整和自动排除继续按各自规则处理，不得被“自动修改最低证据分”混用。

## 四、明确不做的内容

- 不为184条当前路径逐条写死完整字符串规则；
- 不把客户名称、账户名称、金额、凭证号或行号写入通用分类规则；
- 不把所有未知明细统一标成“其他”并冒充完整解释；
- 不改变摘要语义规则、四档分值、十种合法总分或重要性分档；动作表只增加客户选择的自动修改最低分，不改变其他强制检查和人工责任边界；
- 不恢复25元手续费退款的旧自动改判；
- 不新增工作表，不恢复“可靠同类组批量处理”；
- 不重复执行十万行性能测试。

## 五、约束与风险

1. 修复必须落在共享的完整路径解释入口，不能只在车船税调用点加特例。
2. 父属性继承必须服从限制概念和父子关系，防止把“管理费用_设备维修”误判为长期资产、把“生产成本_人工福利”误判为购买商品。
3. 中性限定节点可以不改变候选，但必须保留原文、角色和来源，不能从路径解释中消失。
4. 词典扩充不得通过宽泛子串匹配制造误命中；应复用现有最长词优先、完整路径组合和限制概念机制。
5. 所有中文文件使用UTF-8 with BOM，修改前统一备份至`C:\Users\27651\BackUp\`。

## 六、验收标准

### 6.1 路径完整性红线

- 当前真实样本184条路径的每一个层级都能在覆盖结果中对应到“直接概念、父属性继承、中性限定或未识别槽位”之一；不存在静默丢失节点。
- 固定规则可解释的常见明细不得继续进入未识别槽位；真正无法可靠解释的企业专属明细必须如实保留为待补充。
- 同一个明细词放在不同父路径下时，按完整父子关系形成不同语义或保留歧义，不能由单段词覆盖完整路径。

### 6.2 代表性回归样例

- `税金及附加_车船税`、`应交税费_车船税`、`应交税费_城建税`、`应交税费_地方教育附加`、`应交税费_环境保护税`形成税费方向候选和45分路径证据；
- `应付职工薪酬_社会保险费_养老/医疗/失业/工伤/大病医疗`完整解释为职工薪酬路径，不丢失险种明细；
- `交易性金融资产_募集户/一般户`保留投资属性和账户限定，不因账户类型未识别而降为部分解释；
- `长期股权投资_某公司`保留投资属性和投资对象，但不得把具体公司名称写入通用词典；
- 常见费用层级和明细能够继承正确父语境，同时继续通过设备维修、成本折旧、人工福利、材料采购等反例测试。

### 6.3 真实业务结果

- 360元车船税恢复为摘要25分加完整路径45分，合计70分，按现行动作表自动改入“支付的各项税费”；
- 25元手续费退款继续保留客户原项目，不恢复旧自动改判；
- 当前真实样本的“原表与系统决定差异”应为2项：车船税自动改判1项、内部划转排除1项；实际自动改判计数应为1项。

### 6.4 测试与交付

- 新增测试必须先在旧实现上按预期失败，再以最小实现通过；
- 定向测试、完整普通回归、Skill结构校验、中文编码与异常字符扫描全部通过；
- 只执行一次真实样本冒烟，不重复十万行性能测试；
- 权威设计、SKILL、README及README中的Changelog同步更新；
- 最终提交和推送前重新核对实际变更、测试输出和远端状态。

### 6.5 自动修改最低分选择

- 每次新运行都向客户提供50、55、70、90四个选项，70必须显示为默认和推荐；
- 选择值必须进入运行状态、恢复运行和最终留痕，同一运行不得前后漂移；
- 分别验证选择50、55、70、90时，只有达到所选分数且通过其他动作门禁的业务可以自动修改；
- 非法选项、缺失选择和被篡改的运行状态必须被拒绝，不得静默回退到任意阈值；
- 来源冲突、M3人工责任、内部划转和人工调整等反例不得因选择50而越过原有边界；
- 真实样本冒烟采用推荐默认值70，因此车船税修复后的预期仍为自动改判1项、差异明细2项。

## 七、调研摘要与来源

- 权威设计第9.3节要求保留原始完整路径、标准一级科目、全部原始层级、业务属性及每个判断的原文位置；第10节规定完整路径明确显示税费、投资等属性且能唯一排除其他候选时为45分。
- 权威设计第32.3节禁止单个科目段直接携带项目或分数，要求固定程序按一级科目、中间层级、末级明细和限定词解释完整路径。
- 本次真实运行状态显示184条路径中65条固定规则完整解释、114条部分解释、5条未识别；部分解释关联3,677个业务组成，绝对金额3,679,247,791.04元。
- 代码检查确认：具体税种概念未包含“车船税、城建税、地方教育附加、环境保护税”等常见表达；路径强证据集合也未包含明确的具体税种属性，导致车船税路径候选和45分同时丢失。
- 现有测试覆盖“缴纳车船税”的摘要候选，但没有覆盖`税金及附加_车船税`完整路径，因此未拦住本次回归。

## 八、待确认项

对于“长期股权投资_某公司”“交易性金融资产_募集户”等不会改变现金流大类、但属于完整路径组成的企业专属或账户限定明细，推荐做法是：保留原文并标记为“投资对象/账户限定”，继承已经明确的投资父属性；不把具体名称写入通用词典，也不因为这类中性限定节点而降低完整路径质量。只有该明细可能改变分类时才进入受限Agent。
