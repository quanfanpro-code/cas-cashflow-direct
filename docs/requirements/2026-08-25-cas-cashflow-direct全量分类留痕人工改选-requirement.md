# 全量分类留痕人工改选需求

## 一、背景与问题

当前“全量分类留痕”中的“最终决定项目”主要用于展示程序、AI或已有人工决定形成的结果。除等待人工事项外，已经决定的行是固定内容，使用者不能在该表逐行改选项目。

使用者希望把“全量分类留痕”同时作为最终人工修订入口：默认仍显示本次程序已经形成的决定，但允许对每一条现金流业务组成的分配行重新选择现金流量表项目或“明确排除”。选择后无需重新运行程序，现金流量表正表和正表核对报告应通过Excel公式即时更新。

## 二、用户与使用场景

- 用户：编制或复核直接法现金流量表的财务、审计人员。
- 场景：使用者在查看全量分类留痕时，发现某一条最终项目需要人工调整，直接在该行下拉改选。
- 目标：让人工逐行修订直接进入既有“自动基线＋人工调整＝最终金额”金额桥，同时保留程序原有结果和调整来源。

## 三、已确认需求

### 3.1 最终决定项目

1. “最终决定项目”列默认显示本次工作簿当前已经形成的内容。
2. 每个数据行都提供下拉菜单。
3. 下拉菜单包含22个现金流量表叶子项目和“明确排除”。
4. 下拉菜单不包含“采用系统首选项目”；默认内容本身就是本次工作簿的当前决定。
5. 使用者未改选时，工作簿金额和当前版本完全一致。

### 3.2 人工改选形成的金额

1. 人工从项目A改为项目B时：项目A的人工调整减少该行原列报金额，项目B的人工调整增加按项目B方向形成的列报金额。
2. 人工从项目A改为“明确排除”时：项目A的人工调整减少该行原列报金额，不增加其他项目。
3. 当前决定为“明确排除”或原本没有可列报项目，人工改选项目B时：只增加项目B。
4. 退款或方向不相容的负向金额继续按所选项目的正常流入、流出方向形成带符号列报金额，不把绝对值机械加到目标项目。
5. 同一业务组成分配到多个现金账户时，每个分配行按自己的“本行分配现金变化”计算，不能重复使用整笔业务金额。

### 3.3 与既有人工入口的关系

1. “重要待复核事项”原有人工选择继续有效。
2. 等待人工的全量留痕行默认继续引用“重要待复核事项”的选择。
3. 使用者直接覆盖全量留痕行时，以该行的新选择作为最后一步修订；不得把“重要待复核事项”已经形成的调整重复计算第二次。
4. 程序已导入的人工决定继续保留在既有人工调整初值中；全量留痕的再次改选只计算相对于当前决定的增减，不得重复搬移原金额。

### 3.4 正表联动

1. “现金流量表正表”的“自动基线”保持不变。
2. 全量留痕的人工改选只更新“人工调整”。
3. “最终金额”继续等于“自动基线＋人工调整”。
4. “正表核对报告”的“人工调整”“最终金额”“最终差异”继续引用正表并同步变化。
5. 使用者修改下拉后不需要重新运行Skill；使用Excel打开并启用自动计算即可更新。

### 3.5 留痕与防错

1. 工作簿必须保留计算人工改选所需的原决定、基准项目、基准金额和目标金额，技术列默认隐藏。
2. “最终决定项目”人工输入区使用现有蓝色输入样式。
3. 非下拉值应被Excel数据验证阻止，避免自由粘贴无效项目名称。
4. 所有公式使用项目名称与工作簿行金额，不写客户名称、凭证号、金额或具体样本特例。

## 四、明确不做

- 不改变固定规则、摘要语义、科目路径语义、证据评分或动作路由。
- 不改变自动改判最低证据分。
- 不把人工改选反写到程序数据库、规则词典或自动基线。
- 不新增工作表，不改变十二张工作表的名称和顺序。
- 不取消“重要待复核事项”或“疑似重复事项”现有功能。
- 不重复运行十万行性能测试；本次只运行定向测试、普通回归和一次必要的匿名工作簿冒烟。

## 五、约束与风险

1. Excel下拉项目总文字超过255字符，不能直接把全部项目写入数据验证字符串；必须引用工作表内隐藏单元格区域。XlsxWriter官方文档明确说明该限制。
2. 等待人工事项可能同时从“重要待复核事项”和“全量分类留痕”被操作，公式必须按“当前已有决定→全量留痕最后改选”的顺序计算，避免重复增减。
3. “全量分类留痕”按现金账户分配行展开，公式必须使用分配金额，不能按业务组成整笔金额重复计算。
4. 少数不重新计算公式的第三方表格工具可能仍显示上次缓存值；正式使用以Microsoft Excel自动计算结果为准。

## 六、验收标准

1. 每个全量分类留痕数据行的“最终决定项目”都有下拉，选项恰为22个叶子项目加“明确排除”。
2. 默认值与修改前当前决定一致；未作任何选择时正表金额不变。
3. 自动项目A改为B后，A人工调整减少、B人工调整增加，自动基线不变。
4. 自动项目A改为“明确排除”后，只减少A。
5. 已明确排除行改为B后，只增加B。
6. 等待人工事项通过“重要待复核事项”选择后仍正确联动；随后在全量留痕覆盖为另一项目时只形成一次最终搬移。
7. 已导入人工决定的行保持默认结果；再次改选时不重复计算已有人工调整。
8. 多现金账户分配行逐行调整，合计等于各分配金额之和。
9. 正表核对报告引用正表的人工调整和最终金额，公式链完整。
10. 技术辅助列与下拉选项区域默认隐藏，最终决定项目列保持可见、可选。
11. 输出工作簿结构校验、定向测试和普通回归通过；不重复十万行性能测试。

## 七、调研摘要与来源

- 现有项目已经使用XlsxWriter生成下拉、公式、隐藏技术列和自动计算工作簿，应复用现有实现，不增加依赖。
- XlsxWriter官方说明：列表验证可引用单元格区域；直接字符串列表总长度受Excel 255字符限制，长列表应使用区域引用：[Working with Data Validation](https://xlsxwriter.readthedocs.io/working_with_data_validation.html)。
- XlsxWriter官方说明：公式必须使用英文函数名和英文逗号分隔符，现有`SUMIFS`公式写法符合要求：[Working with Formulas](https://xlsxwriter.readthedocs.io/working_with_formulas.html)。
- XlsxWriter开源项目持续维护并原生支持数据验证，无需引入新的Excel处理依赖：[XlsxWriter GitHub](https://github.com/jmcnamara/XlsxWriter)。

## 八、待确认项

无。用户已确认下拉菜单包含“明确排除”，并授权按上述口径继续实施，不重复确认。
