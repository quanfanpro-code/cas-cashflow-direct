# 业务关系与现金分配修复需求

日期：2026-10-10。
状态：需求范围已由用户在本次对话确认；用户已选择方案A，实施计划由用户授权代理自审后执行。

## 背景与问题

工具能依据已确认现金范围识别真实现金行，但现有业务组成逻辑对多摘要、多笔现金和夹带非现金分录的凭证支持不足：

1. 多现金行分支逐条银行行匹配同摘要业务行，同摘要多条银行行会重复引用业务行；还要求全凭证全部非现金科目行被同摘要现金行覆盖。
2. 单现金行存在不同业务摘要时，后备汇总通过 `_connected_summary` 置空摘要并标记歧义，正常自付、代付也可能被整体隔离。
3. `_minimum_amount_row_combinations` 只保存行数最少的组合，不能证明完整合理分配方案唯一；状态上限导致的搜索未完成也不能当作无解或唯一。
4. `_build_source_allocations` 按同凭证现金行顺序分配金额，未可靠保留已经识别的业务与具体现金行关联。
5. 结构复核请求在运行级提前返回，已确定的独立业务也不能继续语义和分类。

上述为代码核查事实，不以客户名称、凭证号、金额或行号形成生产规则。

## 用户与使用场景

财务、审计人员使用一般企业序时账编制或校验直接法现金流量表。正常业务包括一笔付款结算多个事项、同一事项分多笔付款、工资实发及扣项、同凭证附带独立计提。

## 已确认功能范围

- R1：先确认真实现金来源，再识别业务关系，最后用金额守恒验证；原现流项目不作为关联或分类证据。
- R2：支持一条现金行分配给多个独立业务明细，也支持一个业务组关联多条现金行；保留每条原始记录身份。
- R3：不同业务明细分别保留摘要、完整路径、金额与来源，不因共用一笔付款而合并成一个分类结论。
- R4：工资主项、代扣项和独立计提分别记录。代扣只解释实际支付额，不制造现金收回；独立非现金事项必须有业务事实和借贷闭合依据，净额零不单独构成排除依据。
- R5：同摘要仅为关联线索；金额一致、行数最少和原项目相同均不能单独证明业务归属。
- R6：每行有明确处置：现金来源、业务主项、结算扣项、已确认非现金事项或待解决。不得重复占用金额或静默丢行。
- R7：只有在业务约束下验证为唯一的分配方案才能自动采用。多个有效方案或搜索未完成时保留结构待确认状态。
- R8：已独立确定且不与未决部分争用原始行或现金金额的业务可以继续。未决部分真实现金持续进入桥接；反向现金分别保留，不能靠净额零隐藏未决。
- R9：结构确认不直接给出现金流项目、证据分数或修改权限；分类继续使用现有摘要、路径、独立性、原项目基线、重要性和行动表。依据摘要才能取得的路径关联须保留依赖，防止双计来源。
- R10：结构结论、原文依据、非现金处置和现金分配在运行状态、数据库和留痕中一致；恢复运行不能丢失或重复分配。
- R11：通用规则通过规则中心登记，禁止客户名称、编号、固定金额、行号特例；规则或结构版本变化后新建运行。
- R12：更新 README、相关技能说明及需求/设计/计划/审查文档；保留本次会话先前已验证的字段识别修复，一并交付。

## 明确不做

- 不修改客户原始工作簿或现有规范化副本，不重写旧运行目录，不交付假称最终可用的客户正表。
- 不按金额或摘要相似度强配，不因难以识别而排除真实现金，不按比例分摊缺少依据的业务金额。
- 不扩张分类评分来源、不改变分数及自动修改门槛、不把工资扣项设为新的分类随附规则。
- 不擅自去重同摘要同金额的两条银行记录。
- 不改科目分隔符解释，不新增外部模型服务、依赖或并行agent。

## 约束与风险

- 全程以整数分计算，保持现金逐来源的流入、流出和未决余额守恒。
- 结构候选必须与全部相关分录相容；局部凑齐不证明全局唯一，零和循环不能创造或消除唯一性。
- 暂不能识别的关系进入现有结构复核渠道；无合法候选时不能让AI凭空生成结论。
- 部分业务继续与最终完成是不同状态；所有必需结构/AI/人工事项及最终勾稽仍约束最终状态。
- 保持现有价税关系、内部划转、单边明细、原项目继承和工作簿十四表协议。
- 开发阶段使用通用合成测试；此前读过的真实案例仅作已知问题来源，不在编码阶段继续读取或抄入生产规则；真实文件仅在阶段5只读验收，不入Git。

## 验收标准

| 编号 | 场景 | 应有行为 |
|---|---|---|
| A1 | 单笔付款含自身结算和代付款，两者金额及关系明确 | 两项独立业务共用真实现金来源，各保留自身摘要/路径；合计准确，不预设项目 |
| A2 | 多组工资付款，一组含异摘要借款代扣和独立计提 | 代扣仅影响工资实付额；计提留痕不进现金项目；其他工资组正常保留 |
| A3 | 同摘要两条银行付款与多行主项、扣项 | 可形成同一业务组，保留两条现金来源且不重复占用 |
| A4 | 两个同额利息行分别为代扣和红字计提 | 根据可追溯业务关系区分，不能仅按金额或正负号任选 |
| A5 | 存在一行闭合方案和多行闭合方案 | 不能用最少行掩盖有效的第二方案 |
| A6 | 剩余行净额零但业务联系未知 | 不能自动标为非现金，也不能全部塞入某项业务 |
| A7 | 一组明确、一组歧义 | 明确且无资源争用组继续；歧义金额仍在结构待处理和桥接中 |
| A8 | 现金流入流出净额零但结构未决 | 双向现金及未决状态仍保留，不能当已完成 |
| A9 | 调换行序/科目顺序 | 业务金额及真实来源关联不变；不得退化成按顺序分配 |
| A10 | 超过搜索上限、无候选、伪造行号、重复占用、错误金额、过期候选 | 受控待确认或拒绝导入，禁止自动接受 |
| A11 | 断点恢复、JSON与SQLite一致性、规则升级 | 结果可重现，旧版本不续跑，任务不重复生成 |
| A12 | 已有场景回归 | 内部划转、增值税附属、单边明细、分类独立性、金额桥接和十四表输出无退化 |
| A13 | 本次字段修复 | “凭证字号”和“现金流量”正常识别；金额列/编码子列不被简称误识别为项目 |

真实验收须核对完整凭证来源和金额，不以“所有业务都被自动分类”为通过标准。仍有真实歧义时说明原因和未决金额。
