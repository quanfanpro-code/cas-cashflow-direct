## 一、背景与问题

本批包含三个同级需求：

1. 增值税随基础交易的规则已经写入权威设计和程序，但真实样本中，价款行和进项税行分别填写流量金额后被拆成两个业务组成。程序只在当前组成内部寻找基础交易，导致同凭证、共用同一现金来源的进项税仍被标记为“基础交易缺失”。
2. 摘要和完整路径语义仍有通用能力缺口。复杂外部服务、项目安装、劳务派遣、个税、生产用途及摘要与路径冲突等表达，部分未形成候选，部分被宽泛词语或单段路径机械带到错误候选。
3. 客户自动修改证据档位目前只有50、55、70、90。用户要求新增45分“单强档”：至少存在一个45分强来源，且没有反向证据或任何矛盾，才获得自动修改资格；两个25分形成的纯50分不能借45档自动修改。

系统定位不变：本系统用于发现并纠正已经有正面证据支持的异常，不要求逐笔证明客户原项目正确。原项目有效而修改举证不足时，继续保持原项目。

## 二、用户与使用场景

使用者是编制、校验和复核一般企业直接法现金流量表的财务或审计人员。使用者需要：

- 增值税价税关系按真实现金业务处理，而不是被业务组成拆分方式截断；
- 摘要和完整路径能够理解通用业务关系，同时如实保留真正无法判断的事项；
- 每次运行可以在45、50、55、70、90五档中选择系统自动修改客户原项目的授权档位，70仍为默认和推荐；
- 所有自动修改继续受来源冲突、业务冲突、方向、重要性和人工责任边界约束。

## 三、需求一：修复增值税跨组成继承

### 3.1 同一现金业务的识别边界

“同一现金业务”不得等同于“同一个业务组成对象”。价款和税额即使因为输入已经分别填写流量金额而形成两个业务组成，只要同时满足以下条件，仍可建立基础交易与增值税附属关系：

1. 位于同一张凭证；
2. 共用同一条已确认现金腿或同一笔现金来源分配；
3. 现金方向一致，金额关系能够回到同一现金支付或收取；
4. 一方为进项税或销项税，另一方能够形成基础交易；
5. 基础交易在该现金业务中唯一，不存在多个同样合理的对应关系。

仅有“同一凭证”不足以继承。同凭证中存在多笔独立现金业务、多个基础项目、不同现金腿或金额关系不清时，不得猜测。

### 3.2 基础项目可靠落定条件

增值税只有在基础交易已经形成可靠最终项目时才随其归类：

1. 基础候选与有效原项目一致，且不存在冲突；
2. 系统已经依据本次授权档位完成自动修改或自动补列；
3. 人工已经明确确认基础项目或明确排除基础业务。

基础项目仍待人工、候选不唯一、来源冲突、业务冲突、方向矛盾或输入非法时，增值税不得提前跟随。基础项目需要人工确认时，附属增值税不得再生成一项重复的人工确认任务；工作簿保留该税额的金额和来源明细，并在基础项目人工落定后自动跟随同一项目或同一明确排除决定。只有价税关系本身不唯一或无法建立时，增值税才单独进入人工复核。

### 3.3 继承的证据与金额边界

1. 继承只传递基础交易已经落定的标准项目，不新增第三个证据来源。
2. 不重复计算摘要分、路径分或基础交易分数，不因继承额外加分。
3. 价款和税额金额继续分别保留，合计必须与现金来源分配守恒。
4. 基础项目发生可靠变化时，其附属增值税同步变化；基础项目重新变成未决时，附属增值税也必须停止继承。
5. 只有进项税和销项税适用本机制。福利费、往来款、其他应付款及其他附带分录不得借同凭证候选形成“随交易归类”。
6. 单独缴纳增值税继续归入“支付的各项税费”，不得随采购或销售项目。

### 3.4 输出要求

增值税已经随基础交易时，判断理由必须明确显示：基础交易业务组成、共享现金来源、基础项目及继承依据。不得继续显示“基础交易缺失”。若因此与原项目形成差异，差异表必须明确写成“随唯一基础项目确定”，并把独立评分标记为不适用；不得写成增值税自身0分却“符合自动修改条件”。无法唯一找到基础交易时，继续如实显示缺失或冲突。

## 四、需求二：加强摘要与完整路径语义

### 4.1 固定规则优先

固定程序继续先从摘要中识别并绑定：

1. 现金动作；
2. 交易对象；
3. 对方角色和受益对象；
4. 用途、项目和资产归属；
5. 税款服务对象；
6. 投资、筹资、资本化、退款、冲减及否定关系。

词语只识别业务语素，不能单独决定现金流项目。候选和0、10、25、45分继续由固定程序形成。

### 4.2 本批通用加强范围

本批至少加强以下可跨账套复用的表达族：

1. 外部物流、运输、检测、试验、计量、认证、咨询、评审和委外加工；
2. 安装、搬迁、改造和项目服务，区分客户项目履约、企业自有资产购建及日常维修；
3. 劳务派遣，结合付款对象、人员用途和科目父路径区分外部劳务与职工性质；
4. 工资个税、分红个税、股权激励个税、代缴、补缴和返还，先区分主体、服务对象和现金方向；
5. 电费、水费等生产用途与日常管理用途。只有摘要、完整路径或已确认公司规则明确用途时才形成相应候选，不能仅凭“电费”或收款单位名称推断生产用途；
6. 摘要与完整路径指向不同业务时形成来源冲突，不允许宽泛科目路径压过摘要真实业务，也不允许摘要反向覆盖路径而不留冲突。

完整路径仍必须逐层保留。父级成本或费用语境、末级业务性质和摘要对象共同形成判断；不得采用“最终结转主营业务成本，所以全部属于购买商品、接受劳务”的整批规则。

### 4.3 受限Agent边界

1. 已确认通用句式由固定程序处理。
2. 只有新表达、复杂修饰、多动作绑定、复合分句或表面冲突确实无法由固定程序解释时，才生成受限Agent语义任务。
3. Agent只能补动作、对象、角色、用途、属性、关系及准确原文位置，不得返回项目、候选、质量、分数或处理动作。
4. Agent结果导入后，仍由固定程序重新形成候选和质量。
5. 不启动或操作LM Studio，不接入新的本地或远程模型服务。
6. 自动测试使用构造数据；真实样本只执行一次冒烟，不以调用模型提高覆盖率。

### 4.4 人工表的使用边界

`C:\Users\27651\Desktop\人工改写原项目.xlsx`只用于发现表达族和验证系统留痕，不作为逐行答案或验收金标准：

1. 人工判断本身存在方向、税款主体、投资性质或分类依据问题的行不纳入预期答案；
2. 不把客户名称、金额、凭证号、行号、项目编号或整段摘要写入规则；
3. 正确结果允许是低质量、多候选、来源冲突或没有候选；不得为了贴合人工表强行分类。

## 五、需求三：新增45分单强授权档

### 5.1 客户选择

每次新运行开始前，Agent必须询问：

> 本次系统自动修改客户原项目至少需要哪个证据档位？可选45（单强）、50、55、70、90，推荐并默认70。

客户没有另选时使用70。选择值写入运行状态、恢复运行校验、判断留痕和最终工作簿说明，同一运行不得漂移。

### 5.2 五档授权表

| 客户选择 | 可以进入自动修改判断的总分 | 特别限制 |
|---:|---|---|
| 45（单强） | 45、55、70、90 | 至少一个来源为45分强证据；纯50分不得进入 |
| 50 | 50、55、70、90 | 沿用现有数值门槛 |
| 55 | 55、70、90 | 沿用现有数值门槛 |
| 70（默认、推荐） | 70、90 | 沿用现有数值门槛 |
| 90 | 90 | 沿用现有数值门槛 |

### 5.3 45单强档红线

45单强档获得修改权限必须同时满足：

1. 最终合法总分属于45、55、70或90；
2. 摘要或完整路径至少有一个来源为45分强证据；
3. 候选唯一；
4. 没有来源冲突、业务冲突、公司规则冲突或方向矛盾；
5. 没有非法输入、净额资料缺失、增值税基础交易缺失等强制阻断；
6. 继续服从重要性行动表，M3等人工责任不得因选择45而被绕过。

两个25分中等来源形成的纯50分没有任何强证据，选择45单强档时不得自动修改。客户如希望纯50分可以修改，应明确选择50档。

### 5.4 其他流程不变

45单强档只控制有效原项目拟修改为不同项目时的授权，不改变：

- 原项目为空或无法标准化时的补列流程；
- 内部划转、非现金和现金范围处理；
- 人工调整与自动基线金额桥；
- 来源冲突、业务冲突、重要性和强制检查；
- Agent的证据和决定权限边界。

## 七、测试与验收标准

### 7.1 增值税跨组成继承

1. 未分别填写流量金额的采购价款和进项税继续保持为同一现金业务。
2. 价款和税额分别填写流量金额、形成两个组成，但同凭证且共用现金来源时，增值税能够找到唯一基础交易。
3. 基础项目与原项目一致、系统自动修改、人工确认项目或人工明确排除后，增值税分别能够跟随同一决定。
4. 基础项目未决、多个基础项目、不同现金腿、金额关系不清或存在冲突时不得继承。
5. 单独缴纳增值税继续进入支付税费。
6. 继承前后现金金额、来源分配和正表总额守恒，不重复计算税额。

### 7.2 摘要与路径语义

1. 外部服务、项目安装、劳务派遣、个税、电费用途和摘要路径冲突分别建立不含客户特例的正反例。
2. 固定规则能够解释的句式不得生成Agent任务。
3. 真正需要语言关系补充的复杂表达生成受限任务；非法Agent字段或原文位置继续拒绝。
4. 不能确定用途、主体或资产归属时保留歧义，不为提高候选数强行分类。
5. 完整路径每个节点继续满足直接识别、父属性继承、中性限定或明确未识别，不得静默丢失。

### 7.3 45单强档

1. 选择45时，纯45分单强、55、70、90且无冲突的修改主张可以进入原行动表；纯50分不能进入。
2. 选择50、55、70、90时继续符合原有授权集合。
3. 45分但候选不唯一、来源冲突、业务冲突、公司规则冲突、方向矛盾或强制检查未通过时不得修改。
4. 非法选择、缺失选择和被篡改的运行状态必须拒绝。
5. 提示、运行状态、恢复运行、工作簿说明、README和SKILL使用同一组选项及默认值。
