# cas-cashflow-direct完整路径与可选改判阈值设计

## 一、设计目标

本次同时解决两个相互独立、但都必须进入统一判断中心的问题：

1. 完整科目路径的每个节点都必须被直接识别、继承父属性、标记为中性限定或明确保留为未识别，不得静默丢失中间层级或末级明细；
2. 客户每次运行可以从50、55、70、90中选择自动修改最低证据分，默认并推荐70；该选择只控制有效原项目的自动修改权限，不改变评分和其他门禁。

## 二、方案比较

### 方案A：逐条补当前样本路径

直接把车船税和其余114条部分解释路径逐条写成固定规则。

- 优点：短期覆盖率提升快；
- 缺点：绑定当前账套名称，下一家公司换一种明细名称仍会遗漏；客户名称和账户名称容易进入通用规则；无法证明以后不会再次丢失明细。

结论：不采用。

### 方案B：节点角色完整性＋受控父属性继承＋统一阈值（推荐）

继续复用现有节点概念词典、完整路径组合规则和统一判断中心，只补三项能力：

1. 扩充跨账套可复用的常见明细概念和同义词；
2. 对明确可继承的父属性建立少量受控继承规则，对账户类型、投资对象、费用层级等中性节点保留原文和角色；
3. 把自动修改最低分作为运行参数写入状态，所有修改入口统一读取。

- 优点：修复共同根因；变更集中在现有词典和统一入口；不需要新依赖；能够用构造路径和真实覆盖报告验证；
- 缺点：仍会有真正无法解释的企业专属节点，需要如实保留为未识别或交受限Agent。

结论：采用。

### 方案C：引入完整科目树和中文语义模型

新增科目编码树输入，并引入中文分词、句法或模型解释全部路径。

- 优点：理论覆盖面更广；
- 缺点：当前输入没有稳定的完整科目编码树；依赖和审计成本高；违反固定规则优先、Agent最少参与和本次禁止模型服务的边界。

结论：本次不采用。将来只有真实样本证明名称路径无法满足需求时再单独立项。

## 三、推荐方案的数据流

### 3.1 完整路径

```text
原始完整路径
  → 一级科目标准化
  → 按层拆分且保留原文与位置
  → 节点概念及同义词识别
  → 受控父属性继承
  → 中性限定节点标记
  → 未解释节点形成受限槽位
  → 限制概念优先检查
  → 完整路径组合规则
  → 方向候选
  → 0/10/25/45质量
  → 覆盖留痕
```

每个层级必须在最终结果中有明确记录。未识别节点仍保留原文、位置和允许补充的概念，不得因其他层已形成候选而消失。

### 3.2 自动修改最低分

```text
Agent询问客户：50 / 55 / 70（默认、推荐）/ 90
  → preflight登记
  → 运行状态和运行清单固化
  → 初次统一行动路由读取
  → 后续Agent复核重算读取同一值
  → 差异理由和工作簿使用说明展示
```

缺省技术参数取70，但Skill行为必须在每次新运行前询问客户。客户直接确认推荐值即记录70。旧运行目录因版本变化不得续跑。

## 四、路径节点模型

### 4.1 直接概念

词典继续只输出受控概念，不输出现金流项目和分数。本次补强以下可复用词族：

- 具体税种：车船税、城建税/城市维护建设税、地方教育附加、环境保护税/环保税等；
- 职工薪酬：社会保险费及养老、医疗、失业、工伤、大病医疗等；
- 常见费用：打印装订、电话、招聘、培训、餐费、礼品、公交地铁、打车、搬运装卸、保险、车检、水电、会议、专家服务等；
- 成本和核算层级：费用化支出、直接费用、间接费用、合同履约成本、直接投入、直接材料等；
- 票据和账户限定：应收票据、应付票据、银行承兑汇票、商业承兑汇票、募集户、一般户；
- 宽泛收入、储备和其他节点只识别性质，不强行形成具体项目。

词素仍使用现有规范化和最长命中机制；不能用客户名称、金额、凭证号或行号。

### 4.2 父属性继承

父属性继承由词典中的少量声明控制，不在各调用点写分支：

- `应付职工薪酬`等已识别为职工薪酬父属性时，尚未命中限制概念的后续薪酬明细可继承职工薪酬语境；
- `交易性金融资产、长期股权投资、债权投资`等投资父属性下，尚未命中限制概念的后续账户名称或核算对象标记为投资限定或投资对象；
- 税费父级不对任意未知子节点机械继承，只有命中法定税种同义词后才形成具体税费属性；
- 费用和成本父级只对词典确认的通用层级或费用明细继承语境，未知新词仍保留为未识别，防止掩盖资本化、维修、折旧、职工薪酬或材料属性。

直接识别和限制概念优先于继承。折旧、摊销、结转、减值、维修、资本化、增值税和个人所得税等现有专门规则不得被继承覆盖。

### 4.3 中性限定

募集户、一般户、投资对象、费用化支出、直接费用、间接费用、其他等节点可以不单独改变现金流候选，但必须保留原文、层级、角色和来源。中性限定不能单独加分；完整路径质量仍由能否唯一判断业务决定。

### 4.4 质量规则

- 明确具体税种的完整税费路径为45分强证据；
- 明确职工薪酬类型、投资本金属性、长期资产属性等路径按现有决定性概念规则评45分；
- 只有宽泛父属性或仍缺决定性用途时保持10或25分；
- 有多个候选或内部冲突时不得通过“完整解释”状态提分；
- 固定规则完整解释、Agent补充、部分解释、未识别是覆盖状态，不等于证据分数。

## 五、自动修改阈值模型

### 5.1 合法值

只允许50、55、70、90。统一校验函数负责命令参数、运行状态和调用入口，非法值直接拒绝。

### 5.2 行动关系

阈值只适用于“原项目有效、系统候选与原项目不同”的修改主张：

- M0：分数达到阈值且其他门禁通过时自动修改；否则自动保持；
- M1：分数达到阈值时沿用一次Agent复核后修改的责任边界；未达到时保持；
- M2：沿用既有一次复核或互盲复核深度，但所有允许修改的结果必须达到本次阈值；
- M3：继续人工决定，阈值不能降低人工责任。

来源冲突没有可用总分；非法输入、现金范围、内部划转、金额守恒、公司规则冲突、增值税、个人所得税和净额资料检查继续先于阈值。

### 5.3 Agent复核

所有可能产生`automatic_change`的单轮、双轮和后续互盲结果，都必须通过同一个“达到本次修改阈值”函数。不能保留`{70, 90}`等隐藏硬编码。自动补列继续使用自己的门槛，不受本参数影响。

## 六、代码边界

### 6.1 复用并修改

- `references/科目语义词典.json`：概念、同义词、继承规则和完整路径规则；
- `account_dictionary.py`：逐层概念、继承、中性限定、未识别和质量；
- `decision_policy.py`：合法阈值、动态行动路由和统一判断函数；

- `ai_review.py`：后续复核使用同一阈值；
- `pipeline.py`、`cli.py`：询问结果的技术入口、状态持久化和恢复；
- `workbook_output.py`：在“使用说明与状态”显示本次自动修改最低分。

### 6.2 不新增

- 不新增分类器、外部依赖、模型服务、工作表或配置数据库；
- 不建立当前客户名称词典；
- 不建立第二套评分或行动表。

## 七、错误处理与兼容

- CLI非法阈值由参数校验拒绝；程序调用传入非法阈值由统一校验拒绝；
- 运行状态缺少阈值只允许在新建运行的默认入口登记70，旧版本运行由版本门禁拒绝续跑；
- 同一运行恢复时只读取已登记值，不重新询问或静默变化；
- 词典和行动矩阵版本同时提升，旧路径结果和旧行动结果不得复用；
- 写入的中文JSON、Markdown和运行说明使用UTF-8 with BOM。
