# 全量分类留痕人工改选实施复核

## 一、复核结论

本次需求已经按“自动基线＋人工调整＝最终金额”的既有金额桥实现，没有新建第二套计算中心。

“全量分类留痕”的“最终决定项目”现在默认保留本次工作簿的当前内容，每个数据行均可从22个现金流量表叶子项目和“明确排除”中改选。改选只形成相对于当前决定的增量人工调整，并通过公式联动“现金流量表正表”和“正表核对报告”。

复核未发现阻断问题，可以提交发布。

## 二、需求逐项核对

| 需求 | 实现结果 | 复核结论 |
| --- | --- | --- |
| 最终决定项目默认显示当前内容 | 普通行保留当前决定；等待人工行继续引用“重要待复核事项” | 通过 |
| 每个数据行都有下拉 | 数据验证覆盖“最终决定项目”的全部业务数据行 | 通过 |
| 选项为22个叶子项目加“明确排除” | 23个选项横向放在隐藏辅助区域，避免Excel长列表限制 | 通过 |
| 不改选时金额不变 | 默认决定与隐藏改选基准一致，人工改选生效标志为0 | 通过 |
| 项目A改为B | A的人工调整减少该行基准金额，B增加按B方向形成的目标金额 | 通过 |
| 改为明确排除 | 只从原项目转出，不向其他项目转入 | 通过 |
| 从明确排除或空基准改为项目 | 基准金额为0，只向所选项目转入 | 通过 |
| 重要待复核事项与全量留痕不重复 | 隐藏基准随重要待复核事项的有效决定变化，全量留痕只计算其后的最终改选差额 | 通过 |
| 自动基线保持不变 | 全量留痕公式只追加到“人工调整”；“最终金额”仍为自动基线加人工调整 | 通过 |
| 正表核对报告同步 | 核对报告继续逐项引用正表的人工调整和最终金额 | 通过 |

## 三、共同根因与最小实现

原工作簿已经有“重要待复核事项”和“疑似重复事项”两类人工调整公式，但“全量分类留痕”的最终决定只是展示结果，缺少三个必要条件：可选项目的数据验证、改选前的有效基准、把改选差额并入正表的公式。

本次没有改评分、摘要语义、科目路径语义或动作路由，只复用现有工作簿能力并增加：

1. 一个隐藏的23项下拉来源区域；
2. 四个隐藏技术列，分别保存改选基准项目、基准金额、目标金额和生效标志；
3. 正表每个叶子项目人工调整公式中的一减一加两段汇总；
4. 覆盖默认值、下拉范围、单次搬移和正表引用链的回归测试。

隐藏选项采用横向两行布局，不增加全量留痕的业务行数。项目名称集合在生成前只构造一次，避免在大量留痕行中重复做相同工作。

## 四、重复计算复核

金额顺序固定为：

> 自动基线 → 已导入人工决定或重要待复核事项选择 → 全量分类留痕最后改选

例如原基线为A，“重要待复核事项”先选B，再在“全量分类留痕”改为C：既有公式先形成A转B，全量留痕公式再形成B转C。最终A减少、B净影响为0、C增加，不会把A重复转出两次。

## 五、验证证据

### 5.1 测试先行

- 新增测试在实现前出现2项预期失败：没有逐行下拉、正表人工调整没有引用全量留痕。
- 实现后定向测试为`3 passed, 32 deselected`。
- 工作簿输出受影响测试为`121 passed, 12 subtests passed`。

### 5.2 Microsoft Excel匿名冒烟

| 场景 | 实际重算结果 |
| --- | --- |
| 流入项目A改为流入项目B，金额100 | A人工调整变化-100，B人工调整变化+100 |
| 项目A改为“明确排除”，金额100 | A人工调整变化-100，其他项目不增加 |
| 原基线A，重要待复核事项先选B，全量留痕再选C，金额100 | A变化-100，B变化0，C变化+100 |

以上结果由本机Microsoft Excel完整重算后读取，不是只检查公式文本。

### 5.3 完整常规回归

- 命令：`python -X utf8 -m pytest -q --ignore=tests/test_100k_performance.py`
- 结果：`765 passed, 2 skipped, 119 subtests passed in 51.05s`
