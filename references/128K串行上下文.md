# 128K 串行上下文窗口运行说明

本说明只规定上下文调度如何交接，不替代任何业务规则。业务规则、命令顺序、
任务文件和验收标准仍以 `SKILL.md` 原正文和当前阶段要求的参考内容为准。

## 1. 模式选择与续作

- 每次新任务只询问一次：“本次使用 1M 还是 128K 上下文模型？”
- 选择 1M：按 `SKILL.md` 原正文执行，不创建、不读取任何调度文件，业务行为保持现状。
- 选择 128K：按本说明执行；续作窗口从调度状态继承模式选择，不重复询问。
- 没有活动窗口且用户明确要求变更模式时才允许变更；不得重置或改写业务运行状态。

## 2. 串行独立窗口

- 执行窗口必须前台运行、串行调度：同一时刻最多一个活动模型任务，下一窗口必须等上一窗口结果已由原 `import-*` 命令接受并完成调度登记后才能开始。
- 执行窗口必须使用当前对话正在使用的同一个模型；宿主不能保证同模型时，不启动自动 Agent，改用同模型手工独立对话交接；无法隔离窗口时停止 128K 路径。
- 主控窗口与用户沟通、逐个派发任务；执行窗口只处理分配给自己的任务并返回短回执。
- 主控窗口默认完成 20 次调度后必须轮换（`CONTROLLER_DISPATCH_LIMIT = 20`）；宿主提前发出上下文预警时立即轮换。新主控读取 `交接` 输出和原业务状态续作，不读取旧聊天。

## 3. 任务边界

- 一个执行窗口一次只读取一个现有任务文件（如 `AI复核请求_*.jsonl`、`科目语义待判断_*.jsonl`、`摘要语义待判断_*.jsonl`、`业务组成AI请求_*.jsonl` 等），不重排、不拆并、不得改写原任务，不删字段、不缩批次（原每批最多 25 项不变）、不减少复核。
- 执行窗口必须读取原 `SKILL.md` 和该阶段原本要求的参考规则；本说明不构成省略业务规则的理由。
- 完整任务确实无法装入一个执行窗口时，明确停止并报告，不得通过删减资料硬跑。

## 4. A/B/C 互盲复核

- A、B、C 分别使用新的独立执行窗口，顺序串行：A 保存并导入后才有 B；A、B 形成后续任务后才可能出现 C。
- 每个复核窗口使用不同的 `reviewer_id`，模型仍是当前同一个模型；结果写入不同文件。
- 同一原始后续任务文件可以提供给不同复核窗口，因为其中只有原始任务；每个窗口只回答分配给自己的 `review_round` 和任务编号。
- C 只取得原流程允许它看到的原始任务，不得接触 A/B 结果、主控摘要或比较意见。
- 主控窗口只接收结果路径、哈希和校验状态，不得接收 A/B/C 的专业回答。

## 5. 短回执与导入

- 执行窗口只返回短回执字段：`task_id`、`status`（saved / needs_retry / blocked）、`result_path`、`result_sha256`、`business_anchor_path`、`message`。不得返回逐条专业结论、完整推理或整份 JSONL。
- 主控窗口收到回执后先调用原 `import-*` 命令；只有原程序接受结果后才调用 `完成` 登记调度。文件存在不等于业务完成。
- 原程序拒绝结果时按原失败流程处理；每个任务最多三次技术提交仍由原程序计算，重试使用新的串行窗口并携带原任务和本次校验错误。
- 128K 路径不调用会向对话打印完整运行状态的 `status` 命令；用调度脚本的 `状态` 子命令获取短状态。1M 的原 `status` 用法不变。

## 6. 调度命令

`scripts/串行上下文调度.py` 只使用标准库，命令行子命令：`初始化 / 开始 / 完成 / 状态 / 交接 / 恢复`。

```bash
PY="C:/Users/27651/AppData/Local/Programs/Python/Python314/python.exe"
"$PY" scripts/串行上下文调度.py 初始化 --run-dir <运行目录> --mode 128K --model-binding <当前模型> --backup-root <备份目录>
"$PY" scripts/串行上下文调度.py 开始 --run-dir <运行目录> --task-id <任务编号> --packet <原任务文件> --window-id <窗口标识> --backup-root <备份目录>
"$PY" scripts/串行上下文调度.py 完成 --run-dir <运行目录> --task-id <任务编号> --result <结果文件> --business-anchor <业务锚点文件> --backup-root <备份目录>
"$PY" scripts/串行上下文调度.py 状态 --run-dir <运行目录>
"$PY" scripts/串行上下文调度.py 交接 --run-dir <运行目录>
"$PY" scripts/串行上下文调度.py 恢复 --run-dir <运行目录> --task-id <任务编号> --reason <原因> --backup-root <备份目录>
```

- 调度辅助文件在 `run_dir/计算留痕数据/上下文调度状态.json` 与 `上下文调度记录.jsonl`，只用于调度，不是业务真相；`运行状态.json`、SQLite 和原 JSONL 仍是业务完成与否的唯一依据。
- 覆盖调度状态前脚本自动备份到 `--backup-root` 并做字节校验。

## 7. 异常恢复与停止条件

- 异常中断后，经用户或主控明确确认，用 `恢复` 解除陈旧占用并留痕原因；下一步仍从业务状态判断，不能凭调度记录猜测完成。
- 出现以下情况立即停止并报告，不得降级硬跑：原任务文件无法完整装入执行窗口；不能保证执行窗口使用当前同一模型；无法隔离窗口；调度状态与业务锚点哈希不一致；结果被原 `import-*` 拒绝且重试仍失败。
- 主控窗口即将超限时，完成当前任务的保存和登记后立即 `交接` 轮换，不在中途丢弃未保存工作。
